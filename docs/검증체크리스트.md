# 검증 체크리스트

릴리스 후보를 확인할 때 쓰는 체크리스트다. 자동화 가능한 것은 `npm run verify` 로 묶고,
실제 CLI 세션 동작은 해당 OS에서 직접 확인한다.

---

## 공통 자동 검증

```bash
cd app
npm install
npm run verify
```

`npm run verify` 는 다음을 순서대로 실행한다.

| 단계 | 확인하는 것 |
|---|---|
| `npm test` | runner, CLI 인자 조립, 승인 위험도, worktree 생성 정책·병합, Artifact 분리 등 단위 회귀 |
| `npm run smoke` | 타입 검사, 빌드, 실제 Electron 부팅, 렌더러 로드, runner 감지, 정상 종료 |
| `npm run e2e` | 가짜 CLI로 실제 Electron 세션 시작, 어댑터 이벤트, SQLite 저장·복원 |
| Memory 제안 | 구조화 신호는 대기 제안으로만 저장되고, 승인 시 최신 정본에 추가되며 거절 시 파일이 바뀌지 않음 |
| Skills 3계층 | 같은 이름은 Agent > Project > Global, Required/Available/Disabled가 세션 지침에 정확히 반영됨 |
| Codex Skill 가져오기 | 외부 SKILL.md의 이름·설명·본문·원본 형식·미지원 frontmatter를 저장 전에 표시하고 Global/Project/Agent 범위를 선택한 뒤 편집기로 가져옴 |
| 대화 스크롤 추적 | 하단을 보고 있을 때만 새 응답을 따라가며, 위쪽 내용을 읽는 동안에는 스크롤 위치를 유지하고 하단 이동 버튼을 표시 |
| 승인 후 스크롤 복원 | 다른 세션의 승인 처리를 마치고 원래 세션으로 돌아오면 승인 전 읽던 대화 위치를 복원하며, 같은 승인 세션에 대기 항목이 남아 있으면 아직 복귀하지 않음 |
| 같은 세션 승인 이동 | 위쪽 대화를 읽을 때 하단 승인 요청 개수를 플로팅 표시하고, 누르면 승인 카드로 이동하며 해당 세션의 승인을 모두 처리한 뒤 읽던 위치로 복귀 |
| 자동 커밋 메시지 | 세션 제목이 아니라 diff의 파일·작업 유형을 요약하고 버전 변경은 실제 버전을 제목에 표시 |
| 커밋 직렬화 | 같은 worktree의 자동·수동 커밋이 겹쳐도 `index.lock` 경쟁 없이 하나씩 처리 |

개발 중 빠르게 볼 때는 다음처럼 나눠서 실행한다.

```bash
npm run typecheck
npm test
npm run smoke
npm run e2e
```

## macOS

| 항목 | 기대 결과 |
|---|---|
| `npm install` | 앱 `postinstall`(`install-electron`)이 Electron 바이너리를 받아 `node_modules/electron/dist` 와 `path.txt` 생성 |
| `npm run verify` | 테스트와 Electron smoke 통과 |
| `npm run dev` | 앱 창이 뜨고 runner 감지 목록 표시 |
| macOS 앱 아이콘 | Dock과 앱 전환기에 Puppeteer 아이콘이 표시 |
| 공개 Agent 가져오기 | GitHub의 `agents/release-maintainer.md` blob URL을 붙여 전문·요청 권한을 검토하고 라이브러리에 저장 가능 |
| 공개 Agent Linked 갱신 | Linked 저장 후 Git 원본을 바꾸면 업데이트 감지되고 로컬 적용 대상·허용 권한은 유지 |
| Memory 즉시 제안 | AI 제안 발생 시 대화에서 내용·이유·범위를 보고 즉시 승인, 거절 또는 Memory 검토 가능 |
| Memory 검토함 안내 | Memory 진입 시 최신 대기 제안을 자동 선택하고 좌측에서 승인 위치를 명확히 안내 |
| Memory 작은 창 레이아웃 | 긴 경로·diff가 오른쪽을 밀지 않고 편집 영역 자체 스크롤로 하단 승인·저장 UI까지 접근 가능 |
| Memory 여러 제안 구분 | 각 제안마다 대상 범위·이유·추가될 내용·결정 버튼을 한 카드로 표시하고 전체 정본 diff는 강제하지 않음 |
| Memory 전역 승격 | Project·자동·Agent Memory에서 선택한 내용만 실행환경별 전역 정본에 복사되고 원본은 유지되며 동일 내용은 중복되지 않음 |
| Memory 저장 단축키 | Memory 편집 중 Ctrl+S 또는 Cmd+S가 기본 저장 동작을 막고 현재 정본을 저장하며 기존 Ctrl+Enter도 유지 |
| 설정 도움말 | 설정 도움말이 단축키·예약 지시·이미지 첨부·이동·승인 팁을 표시하고 Esc·바깥 클릭으로 닫힘 |
| Claude/Codex POSIX 설치 | `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.npm-global/bin`, `~/.bun/bin` 중 설치 경로 감지 |
| 새 세션 자동 격리 | 별도 조작 없이 `puppeteer/<세션8자>` 브랜치와 worktree가 생성되고 상단에 표시 |
| 정리 후 세션 재개 | 정리 직후 `Worktree 정리됨`이 표시되고, 후속 지시 시 현재 원본 HEAD에서 새 worktree와 고유 브랜치 생성 |
| 프로젝트별 Worktree 정책 | 프로젝트 목록에서 사용 안 함·병합 제안·자동 병합을 각각 저장하고, 새 세션의 격리 및 완료 후 Git 반영이 선택대로 동작 |
| Worktree 사용 안 함 | 새 세션이 원본 폴더에서 실행되며 완료 시 자동 커밋·병합을 시도하지 않음 |
| 사용 안 함 전환 정리 | 프로젝트의 기존 Worktree가 모두 clean·병합 완료 상태일 때만 일괄 정리하고, 하나라도 위험하면 정책 변경 없이 정확한 경로와 원인을 표시 |
| 끊어진 worktree 재개 | DB 기록만 남고 Git 등록이 사라진 worktree는 기존 폴더를 보존한 채 별도 경로의 새 worktree로 재개 |
| 끊어진 worktree 정리 | Git 등록이 이미 사라진 경우 기존 폴더를 삭제하지 않고 DB 연결만 해제하며 다음 지시에서 재생성 가능 |
| 자동 분리 실패 폴백 | Git 저장소가 아닌 프로젝트에서는 경고 후 현재 폴더에서 세션 시작 |
| 원본 변경 경고 | 원본에 미커밋 파일이 있으면 새 worktree에 포함되지 않는다는 경고 표시 |
| worktree 병합 | 커밋된 작업은 원본 브랜치로 fast-forward되고, 미커밋·분기 상태에서는 이유를 표시하며 차단 |
| 자동 작업 반영 | 기본 `자동 병합`에서 정상 완료 시 변경을 자동 커밋하고 안전한 fast-forward로 원본에 반영 |
| 병합 제안 모드 | 설정 변경 후 정상 완료 시 자동 커밋하지 않고 대화에 worktree `cd` 경로와 실행·수동 병합 안내 표시 |
| 자동 병합 폴백 | 원본 미커밋 변경·브랜치 분기 등 안전 조건 실패 시 원본을 더 바꾸지 않고 병합 제안 표시 |
| 변경 없는 완료 | Git 상태만 확인하고 새 커밋이나 병합을 만들지 않음 |
| 자동 반영 완료 안내 | 자동 커밋과 fast-forward 병합 성공 후 세션 대화에 완료 안내 표시 |
| 자동 반영 진단 | Worktree 화면에서 마지막 자동 처리 단계·시각·경로·Git 상태·실패 원인을 접어서 확인 가능 |
| 자동 반영 진단 유지 | 앱을 다시 열어도 해당 세션의 마지막 자동 반영 결과가 Worktree 화면에 유지됨 |
| 자동 반영 기록 복구 | 완료된 세션에 미반영 변경이 있고 진단 기록이 없으면 Worktree 화면을 열 때 자동 처리를 한 번 복구 |
| 중단된 자동 반영 복구 | 확인·커밋·병합 중 기록이 30초 넘게 정체되면 Worktree 화면을 열 때 현재 Git 상태부터 재개 |
| 자동 커밋 후 UI 갱신 | 미커밋 변경을 자동 반영한 뒤 커밋 입력 영역이 사라지고 최종 반영 상태가 표시됨 |
| 자동 병합 완료 알림 축소 | 완료 문구를 처음에는 펼쳐 보이고, 사용자가 스크롤하거나 입력하면 애니메이션과 함께 성공 아이콘으로 축소 |
| 자동 병합 완료 알림 재확인 | 축소된 성공 아이콘을 누르면 완료 문구를 다시 펼쳐 확인 가능 |
| 자동 병합 알림 레이아웃 | 완료 알림을 입력창 위 오버레이로 표시해 축소 전후 대화 높이·스크롤 위치가 변하지 않음 |
| 자동 병합 알림 중복 | 같은 세션의 과거 완료 알림은 겹쳐 띄우지 않고 최신 알림 하나만 표시 |
| 자동 병합 알림 위치 | 대화 영역 우측 전송 버튼 위에 표시하고 Artifact 패널 너비가 바뀌어도 함께 이동 |
| 축소 아이콘 외형 | 축소 후에는 배경·테두리·그림자 없이 체크 아이콘만 표시 |
| 축소 아이콘 호버 | 체크 아이콘에 마우스를 올리거나 키보드 포커스하면 완료 문구가 펼쳐지고 벗어나면 다시 축소 |
| 완료 알림 안정성 | 호버 대상은 아이콘 크기로 고정하고 별도 팝오버의 투명도·위치만 전환해 깜빡임과 내용 재배치를 방지 |
| 완료 알림 렌더링 성능 | backdrop blur를 사용하지 않고 GPU opacity·transform만 짧게 전환해 축소 시 프레임 저하 방지 |
| 세션 도구 모음 | 실행환경·Agent·반영 상태가 독립 버튼과 오버레이로 열리고, 전체 접힘 시 얇은 핸들만 남음 |
| 세션 도구 레이아웃 | 펼침·접힘과 오버레이 표시가 입력창·대화 높이를 불필요하게 흔들지 않음 |
| 대화 하단 이동 | 하단에서 벗어났을 때만 우측 아래 버튼이 나타나고 클릭 후 하단 도달 시 숨김 |
| 긴 문자열 줄바꿈 | 공백 없는 긴 구분선·경로·출력이 대화 폭을 늘리거나 가로 스크롤을 만들지 않음 |
| 우측 패널 탭 | 지시·Git·Artifacts·Files 전환과 전체 접기가 동작하고 선택 배경과 글자 대비가 두 테마에서 충분함 |
| 지시 탐색 | 지시 탭이 가장 앞에 표시되고 사용자 입력을 시간순으로 나열하며 선택 시 해당 대화 위치로 이동 |
| 비 Git 프로젝트 | Git 저장소가 아닌 프로젝트에서는 Git 탭을 표시하지 않음 |
| Git 이력 | 최근 커밋 제목·해시·작성자·시각·ref가 최신순으로 표시됨 |
| Git/Worktree 상태 | dirty, ahead/behind, fast-forward 가능 여부와 마지막 자동 반영 결과가 새로고침 후 일치함 |
| Worktree 관리 축소 | 중복 조회 정보는 관리 창에서 빠지고 커밋·rebase·병합·충돌 해결·정리 동작은 유지됨 |
| 파일 미리보기 | 프로젝트·worktree 파일을 읽기 전용으로 열고 바이너리·1MB 초과 파일은 이유를 표시 |
| 사용량 기본 접힘 | 시작 시 아이콘·사용량 레이블·진행률·퍼센트만 표시하고 펼치면 상세 내역 표시 |
| 실행 중 창 닫기 | 실행 중인 세션이 있으면 종료 전 확인하며 취소하면 창과 세션이 유지됨 |
| 프로젝트 별칭 | 기본 폴더명이 표시되고, 별칭 변경 후 재시작해도 별칭이 유지되며 빈 별칭은 폴더명으로 복귀 |
| 프로젝트 경로 재연결 | 이동한 원본 폴더 선택 후 프로젝트·세션·worktree·Agent 범위가 새 경로를 사용하고 기존 대화가 유지됨 |
| 재연결 안전선 | 실행 중 세션, 중복 등록 경로, Git worktree 복구 실패에서는 DB와 정본 파일을 변경하지 않음 |
| 삭제된 worktree 재연결 | DB에만 남은 과거 worktree 폴더는 Git repair에서 제외하고 세션 기록과 새 원본 참조는 유지 |
| 승인 후 복귀 | 다른 프로젝트·세션에서 승인 항목을 열어 승인/거부하면 직전에 보던 위치로 자동 복귀 |
| 다중 승인 후 복귀 | 같은 승인 세션에 요청이 여러 개면 마지막 요청 처리 전까지 이동하지 않음 |
| 대화 아티팩트 연결 | 본문 아티팩트 카드를 누르면 우측 패널이 열리고 아티팩트 탭의 해당 항목이 선택됨 |
| 기본 실행환경 일치 | 설정한 환경이 프로젝트·세션 환경이 없는 새 세션에서 실제 실행 환경으로 사용됨 |
| 예약 지시 세션 격리 | 예약한 세션에서는 표시되고 다른 세션에서는 숨지만 대상 종료 후 원래 세션에 전송됨 |
| 승인 생명주기 | 앱 재시작·세션 종료 시 미결 승인을 폐기하고 보류 항목을 직접 삭제 가능 |
| 승인 후 상태 | 승인·거부 처리 뒤 남은 승인 요청이 없으면 세션 표시가 `승인 대기`에서 `실행 중`으로 복귀 |
| 승인 단축키 | 최신 승인 카드에서 Space는 이번만 허용, Enter는 세션 허용, Esc는 거부로 동작하며 입력창 타이핑 중에는 발동하지 않음 |
| 입력 기록 탐색 | 입력창 첫 위치에서 ↑를 누르면 프로젝트별 이전 지시를 불러오고 ↓로 현재 초안까지 복귀 |
| 프로젝트·세션 키보드 탐색 | Alt+↑/↓로 프로젝트를, Alt+←/→로 현재 프로젝트의 세션을 순환하며 입력창의 ↑/↓ 기록과 충돌하지 않음 |
| 세션 이름 변경 | 세션 탭의 연필 버튼·더블클릭으로 이름을 바꾸고 Enter/포커스 이탈로 저장, Esc로 취소하며 재시작 후에도 유지 |
| 프로젝트 순서 변경 | 프로젝트를 드래그해 순서를 바꾸면 즉시 반영되고 앱 재시작 후에도 같은 순서가 유지됨 |
| 기존 대화 기록 | 기능 추가 전 세션도 대화에 저장된 사용자 메시지를 ↑/↓ 입력 기록에 포함 |
| 반복 입력 기록 순서 | 같은 지시를 다시 사용한 경우 오래된 위치가 아니라 가장 최근 입력 위치를 ↑ 기록에 유지 |
| 실행 중 다음 지시 | 세션 실행 중에도 입력 가능하며 Enter로 다음 지시 한 건을 예약하고 현재 작업 완료 후 자동 전송 |
| 완료 세션 알림 | 세션 완료 시 우측 아래 토스트가 아래에서 올라오고, 클릭하면 해당 대화로 이동하며 X 또는 대화 진입 시 우측으로 사라짐 |
| 세션 순서 영속화 | 세션 탭을 드래그해 바꾼 순서가 프로젝트 재진입·앱 재시작 후에도 유지됨 |
| 세션 숨김·복원 | 실행·승인 대기가 아닌 세션을 숨기면 탭에서 빠지고, 더보기의 숨긴 세션에서 복원 가능 |
| 다음 지시 취소 | 예약된 지시를 입력창 위에서 확인하고 전송 전에 취소 가능 |
| 예약 대상 고정 | 예약 시점의 세션 ID·CLI 세션 ID·러너를 사용해 새 세션이 아닌 기존 세션으로 명시적 재개 |
| 진단 저장 실패 격리 | 진단 테이블 저장 실패가 실제 자동 커밋·병합을 중단시키지 않음 |
| 병합 완료 상태 | 다른 세션 병합으로 원본보다 뒤처져도 이미 병합된 worktree에는 불필요한 `원본 변경 반영` 버튼 미표시 |
| worktree 충돌 해결 | 원본 변경 반영 중 충돌이 나면 새 해결 창이 열리고, 파일 목록과 좌우 코드에서 선택 적용 가능 |
| 연속 충돌 | 여러 커밋에서 다시 충돌하면 같은 해결 창에 다음 충돌 파일이 표시되고 마지막 해결 후 병합 버튼 활성화 |
| 삭제·바이너리 충돌 | 삭제 여부 또는 바이너리 파일 전체에서 사용할 쪽을 선택해 내용 훼손 없이 반영 |
| 충돌 해결 취소 | 해결 창을 닫으면 진행 중 rebase가 abort되고 Worktree 관리 화면이 이전 상태로 갱신 |

### macOS 설치본·업데이트

Intel과 Apple Silicon을 한 설치본으로 지원하는 Universal 앱을 만든다. DMG는 설치용이고 ZIP은
macOS 자동 업데이트 메타데이터 생성에 반드시 함께 필요하다.

```bash
cd app
npm run dist:mac
```

| 항목 | 기대 결과 |
|---|---|
| Universal 패키지 | `Puppeteer-<버전>-mac-universal.dmg`, `.zip` 생성 |
| 업데이트 메타데이터 | `latest-mac.yml` 생성, ZIP 정보 포함 |
| 승인 훅 포함 | 앱 번들의 `Contents/Resources/hooks/approve.sh`, `approve.ps1` 존재 |
| Intel 실행 | x64 Mac에서 설치·실행 및 Claude/Codex 감지 |
| Apple Silicon 실행 | arm64 Mac에서 설치·실행 및 Claude/Codex 감지 |
| 서명 확인 | `codesign --verify --deep --strict Puppeteer.app` 통과 |
| 공증 확인 | `spctl --assess --type execute --verbose Puppeteer.app` 통과 |
| 업데이트 왕복 | 낮은 버전 설치 → 새 Release 감지 → ZIP 다운로드 → 재시작 설치 |

서명 secret이 없으면 GitHub Actions는 unsigned DMG·ZIP을 게시한다. 이 파일은 사용자가 Gatekeeper
경고를 직접 우회해야 하며, 위의 서명·공증 확인 항목은 적용되지 않는다. GitHub 저장소에 아래
Actions secrets를 모두 설정하면 electron-builder가 Developer ID 서명과 Apple 공증을 수행한다.
일부 secret만 설정된 상태는 구성 오류로 보고 릴리스 전에 실패시킨다.

- `MAC_CSC_LINK`: Developer ID Application 인증서 `.p12`의 base64 또는 다운로드 가능한 보안 URL
- `MAC_CSC_KEY_PASSWORD`: `.p12` 암호
- `APPLE_ID`: 공증에 쓸 Apple ID
- `APPLE_APP_SPECIFIC_PASSWORD`: 앱 전용 암호
- `APPLE_TEAM_ID`: Apple Developer Team ID

| 공개 Agent 생성 도우미 | `agents/agent-creator.md`를 가져와 Puppeteer 형식 초안을 만들고 승인 전에는 파일을 쓰지 않음 |

## Windows 설치본·업데이트

설치 파일은 Windows PowerShell에서 만든다.

```powershell
cd app
npm run dist:win
```

`app/dist_electron/`에 NSIS 설치 파일, `latest.yml`, blockmap이 함께 생겨야 한다.

| 항목 | 기대 결과 |
|---|---|
| unpacked 패키지 | `npm run pack` 후 `win-unpacked/Puppeteer.exe` 실행 가능 |
| 승인 훅 포함 | `win-unpacked/resources/hooks/approve.ps1`, `approve.sh` 존재 |
| NSIS 설치 | 설치 위치 선택, 바탕 화면·시작 메뉴 바로가기 생성, 앱 실행 |
| 작업표시줄 아이콘 | 실행 중 Puppeteer 아이콘으로 표시되고 Electron 기본 아이콘이 보이지 않음 |
| 사용자 데이터 유지 | 개발 실행 또는 이전 설치본의 프로젝트·세션 DB를 새 버전에서도 읽음 |
| 자동 확인 | 설치본 시작 뒤 새 버전이 있으면 설정 아이콘에 점 표시 |
| 명시적 다운로드 | 사용자 클릭 전에는 내려받지 않고, 클릭 뒤 진행률 표시 |
| 재시작 설치 | 다운로드 완료 뒤 `재시작해 설치`로 종료·설치·재실행 |
| 실패 노출 | 네트워크·릴리스 오류가 설정 화면에 표시되고 재확인 가능 |

실제 업데이트는 같은 버전끼리 시험할 수 없다. 낮은 버전을 설치하고 더 높은 버전의 GitHub
Release를 게시해 전체 왕복을 확인한다. v0.0.1 → v0.0.2 Windows 왕복을 처음 확인했고, 이후
`v0.0.9`까지 같은 절차로 태그를 게시해 설치본 업데이트를 반복 확인했다. 릴리스에는
설치 파일만이 아니라 electron-builder가 만든 `latest.yml`과 blockmap도 함께 올라가야 한다.

`app/package.json`과 `app/package-lock.json`의 버전을 함께 올려 커밋한 뒤 같은 버전 태그를 푸시한다.

```powershell
cd app
npm version patch --no-git-tag-version
cd ..
git add app/package.json app/package-lock.json
git commit -m "chore: release v0.0.2"
git tag v0.0.2
git push origin main
git push origin v0.0.2
```

`.github/workflows/release.yml`이 태그 push를 받으면 검증·패키징하고 GitHub Release에
산출물을 게시한다. 게시 전에 preflight job이 `package.json` 버전과 태그를 검사한다.
macOS 서명·공증 secret이 하나도 없으면 Windows 전용 Release를 만들고, 5개가 모두 있으면
같은 Release에 Universal DMG·ZIP을 추가한다. 일부 secret만 설정된 상태는 구성 오류로 중단한다.

Windows job은 NSIS 설치 파일, blockmap, `latest.yml`, 번들 승인 훅을 모두 확인한 뒤에만
Release를 생성한다. 따라서 태그를 올린 뒤 파일을 GitHub 웹 화면에서 직접 업로드할 필요가 없다.
