# 검증 체크리스트

v0.0.1 후보를 확인할 때 쓰는 체크리스트다. 자동화 가능한 것은 `npm run verify` 로 묶고,
실제 CLI 세션 동작은 해당 OS에서 직접 확인한다.

---

## 공통 자동 검증

```bash
cd app
npm install
npm run verify
```

`npm run verify` 는 다음을 순서대로 실행한다.

| 단계 | 확인하는 것 |
|---|---|
| `npm test` | runner, CLI 인자 조립, 승인 위험도, Artifact 분리 등 단위 회귀 |
| `npm run smoke` | 타입 검사, 빌드, 실제 Electron 부팅, 렌더러 로드, runner 감지, 정상 종료 |

개발 중 빠르게 볼 때는 다음처럼 나눠서 실행한다.

```bash
npm run typecheck
npm test
npm run smoke
```

## macOS

| 항목 | 기대 결과 |
|---|---|
| `npm install` | Electron postinstall 이 완료되고 `node_modules/electron` 사용 가능 |
| `npm run verify` | 테스트와 Electron smoke 통과 |
| `npm run dev` | 앱 창이 뜨고 runner 감지 목록 표시 |
| Claude/Codex POSIX 설치 | `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.npm-global/bin`, `~/.bun/bin` 중 설치 경로 감지 |

## Windows 네이티브

PowerShell에서 실행한다.

```powershell
cd app
npm install
npm run verify
npm run dev
```

| 항목 | 기대 결과 |
|---|---|
| Windows native runner 감지 | `where claude`, `where codex` 결과가 앱에 표시 |
| npm shim 실행 | `.cmd` / `.bat` 실행 파일이 `cmd.exe /c` 로 감싸져 `spawn EINVAL` 이 나지 않음 |
| 새 세션 시작 | 첫 지시 후 세션 탭이 하나 생기고 상태가 `running` 또는 `completed` 로 이동 |
| 이어가기 | 같은 세션에 후속 지시를 보내도 앱 세션 탭이 새로 늘지 않음 |
| 인증 실패 | 미로그인 CLI는 `auth-required` 로 끝나고 안내 카드가 표시 |

## Windows + WSL

Windows PowerShell에서 앱을 실행하고, CLI는 WSL 배포판 내부 설치본을 사용한다.

```powershell
cd app
npm install
npm run verify
npm run dev
```

| 항목 | 기대 결과 |
|---|---|
| WSL 배포판 감지 | `wsl.exe -l -q` 의 배포판별 runner 표시 |
| WSL CLI 절대경로 | runner executable 이 `/home/.../bin/claude` 또는 `/home/.../bin/codex` 같은 절대경로 |
| WSL 작업 경로 | 세션 실행 명령이 `wsl.exe -d <distro> --cd <Windows 프로젝트 경로> -- <절대경로>` 형태 |
| Claude 새 세션 | WSL Claude로 새 세션 시작 가능 |
| Claude 이어가기 | 후속 지시에서 `--resume <id>` 가 동작하고 앱 세션 탭이 늘지 않음 |
| Codex 새 세션 | WSL Codex로 새 세션 시작 가능 |
| Codex 이어가기 | `codex exec ... resume <id> <prompt>` 순서로 동작하고 `unexpected argument '--sandbox'` 가 나지 않음 |
| 승인 요청 | Write/Edit/Bash 승인 요청이 앱에 뜨고 허용/거부 결과가 CLI에 전달 |
| 승인 시간초과 | 응답 없이 제한 시간을 넘기면 왼쪽 승인 알림이 사라지고 세션에 보류 안내가 남음 |
