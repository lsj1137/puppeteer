제품 정의와 기능 명세는 `기획서.md` 참조. 이 문서는 구현 방식만 다룬다.

## 1. 확정 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 셸 | Electron + electron-vite | 메인 프로세스가 Node → 프로세스 제어·git·SQLite 직결 |
| UI | React + TypeScript + Tailwind + shadcn/ui | |

| Artifact 뷰어 | **shiki** | 읽기 전용 뷰어에 Monaco(에디터, 5MB+·웹워커)는 과함. 문법강조·줄번호·diff 모두 커버하고 **Catppuccin 테마를 기본 제공** |

| 이미지 Annotation | react-konva | 사각형·화살표·번호·텍스트 → PNG export |
| Git / Worktree | `child_process.execFile` + Git CLI | 셸 문자열 없이 인자 배열로 호출해 Windows·macOS 경로를 같이 지원 |
| 파일 감시 | chokidar | (미착수) |
| DB | **`node:sqlite`** (Node 24 내장) | 아래 참조 |

> 네이티브 빌드·다운로드·컴파일러가 전혀 필요 없다. 스키마는 `src/main/db.ts` 에 직접 작성한다.

## 2. 프로세스 모델

```
Electron Main
 ├ SessionManager        세션 생명주기, DB 적재, 렌더러 중계
 ├ ClaudeCliAdapter ×N   CLI 프로세스 1개당 1 인스턴스
 ├ ApprovalBroker        승인 요청 파일 감시 + 응답 기록
 ├ db (node:sqlite)      project / session / event / approval
 └ runner-detect         Windows·WSL·POSIX 실행 환경 탐지

Renderer (React)
 └ Rail(프로젝트·세션·승인·실행중) · 대화 · Artifact 패널 · Command Palette
```

이벤트는 `sessionId` 로 라우팅되어 렌더러가 세션별 상태를 따로 쌓는다. 화면에 보이지 않는 세션도 백그라운드에서 계속 진행된다.

## 3. CLI Adapter

두 축을 분리한다.

```
Session = Provider × Runner

Provider (무엇)              Runner (어디서)
├ claude-agent-sdk           ├ windows-native  → claude.exe
├ claude-cli                 ├ wsl             → wsl.exe -d <distro> -- claude
└ codex-cli                  └ custom          → 사용자가 명령·인자 직접 지정
```

| Provider | 통신 | 승인 인터셉트 | Resume | 상태 |
|---|---|---|---|---|
| `claude-cli` | spawn + `--output-format stream-json` | hook → HookServer 질의 | `--resume <id>` | **v1 주 경로 (실측 완료)** |
| `claude-agent-sdk` | in-process `query()` | `canUseTool` 콜백 | SDK 세션 ID | v2 선택지 (미검증) |
| `codex-cli` | spawn + JSON 이벤트 스트림 | Codex 프로토콜 정규화 | Codex 세션 ID | v2 진행 |

> **전제 변경.** 초기 설계는 hook 경로의 승인 타임아웃을 이유로 Agent SDK를 주 경로로 삼았다. 스파이크 결과 hook `timeout` 설정이 적용되고 만료 시에도 세션이 죽지 않음을 확인해, **hook 경로를 v1 주 경로로 확정**한다. Agent SDK는 Windows 최적화용 선택지로 격하한다. 근거: `spike/REPORT.md` S2.

### 정규화 이벤트 스키마

세 어댑터가 동일 타입으로 정규화해 올린다. **아래는 Claude CLI 2.1.220 실측 기준.**

```ts
type SessionEvent =
  | { t:'status';   status: SessionStatus }
  | { t:'message';  role:'assistant'|'user'; text:string }
  | { t:'artifact'; kind:'code'|'md'|'diff'|'image'|'log'; path?:string; content:string }
  | { t:'approval'; id:string; tool:string; input:unknown; cwd:string; risk:'low'|'med'|'high' }
  | { t:'file-changed'; path:string }
  | { t:'usage';    inputTokens:number; outputTokens:number; cacheRead:number; costUsd?:number }

type SessionStatus =
  | 'starting' | 'running' | 'waiting-input' | 'approval-required'
  | 'completed' | 'failed' | 'stopped' | 'disconnected' | 'auth-required'
```

### CLI 이벤트 → SessionEvent 매핑 (실측)

| CLI 이벤트 | 추출 | SessionEvent |
|---|---|---|
| `system`/`init` | `session_id`, `cwd`, `model`, `permissionMode`, `tools[]`, `memory_paths`, `claude_code_version`, `apiKeySource` | `status:'running'` + 세션 메타 저장 |
| `rate_limit_event` | `rate_limit_info.status` / `resetsAt` / `rateLimitType` | 상태 바 rate limit 표시 |
| `assistant` (text 블록) | `message.content[].text` | `message` — 코드펜스 파싱 대상 |
| `assistant` (tool_use 블록) | `name`, `input`, `id` | 도구 실행 표시 / 변경파일 추적 |
| `user` (tool_result) | **`tool_use_result.stdout` / `.stderr`** | `artifact` (kind:`log`) — 파싱 불필요 |
| `system`/`thinking_tokens` | | 진행 표시 |
| `result` | `total_cost_usd`, `usage`, `modelUsage` | `usage` — **자체 계산 불필요** |
| `result` | `permission_denials[]` | 승인 거부 이력 → Inbox 반영 |
| `result` | `terminal_reason`, `is_error` | `status:'completed'|'failed'` |

주의: `assistant` 이벤트는 **콘텐츠 블록 단위로 분할되어 오고 같은 `message.id`를 공유**한다. 어댑터에서 `message.id`로 묶는다.

## 4. 승인 구현

### 실측 결과 (`spike/REPORT.md` S2)

| 항목 | 결과 |
|---|---|
| hook `timeout: 300` 설정 | **적용됨** — 20초 지연 hook이 완주 |
| 만료·거부 시 세션 | **죽지 않음** (`is_error:false`, `terminal_reason:completed`) |
| deny 사유 문구 | **모델에게 전달되고 인용됨** → 보류 지시가 실제로 통함 |
| 거부 이력 | `result.permission_denials[]`에 구조화 기록 |

### 실행 환경은 세션마다, 시작 후에는 잠근다

러너는 **세션 단위**로 정한다(`session.runner_id`). 프로젝트 러너는 새 세션의 기본값일 뿐이다.
한 프로젝트에서 탭 하나는 Claude, 다른 탭은 Codex 로 돌릴 수 있다.

**세션이 시작되면 못 바꾼다.** 세션 기록이 러너 홈마다 따로 있어

```
WSL     ~/.claude/projects/          194
Windows %USERPROFILE%\.claude\       38
Codex   ~/.codex/sessions/             7
```

바꾸는 순간 `--resume` 이 통하지 않는다. 바꿀 수 있게 두고 경고하는 것보다
**아예 잠그고 새 세션을 열게** 하는 편이 낫다 — 경고는 읽히지 않는다.
`run()` 에도 러너 불일치 시 resume 을 끊는 방어를 남겨 둔다.

승인 요청의 `cwd`는 격리된 worktree 경로일 수 있다. 승인 상세와 위험도 판정에는 이 실제
실행 경로를 유지하되, Rail·Overview·명령 팔레트·OS 알림에서 세션을 열 때는 DB의
`session.project_path`를 `projectPath`로 함께 전달한다. 후속 명령도 열린 세션의 저장된
프로젝트 경로를 우선해 worktree 폴더가 별도 프로젝트로 등록되는 일을 막는다.

### 모달

배경 흐림은 **2px 까지만.** 그 이상은 뒤 내용이 뭉개져 맥락이 끊긴다.
어둡기(`bg-crust/60`)로 초점을 만들고 흐림은 거들기만 한다.

### 설정 주입 — 사용자 파일을 건드리지 않는다

실제 사용자 환경에 **이미 다른 도구가 hook 11종을 `~/.claude/settings.json`에 등록**해 둔 사례를 확인했다. 앱이 이 파일을 편집하면 해당 도구가 깨진다.

→ 앱은 **세션 단위로 `--settings` 인자에 JSON 문자열을 주입**한다. 기존 hook과 공존하며 잔여물이 남지 않는다. 동작 확인 완료.

```
--settings '{"hooks":{"PreToolUse":[{"matcher":"Bash","hooks":[
  {"type":"command","command":"<앱 hook 경로>","timeout":300}]}]}}'
```

사용 가능한 hook 이벤트: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `UserPromptSubmit`, `Stop`, `StopFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `TeammateIdle`, **`PermissionRequest`**

### 4겹 방어

| 순서 | 방법 | 담당 | 상태 |
|---|---|---|---|
| 1 | hook `timeout`을 크게 설정 (300s 이상) | Adapter | 실측 확인 |
| 2 | 사전 권한 정책으로 승인 빈도 축소 | Adapter (hook matcher) | 구현 |
| 3 | Rail·상태바 승인 배지와 OS 알림 | Renderer/Main | 구현 |
| 4 | 만료 시 거부 + 보류 복구 | hook 스크립트 | 실측 확인 |

### hook 경로 흐름

**HTTP 가 아니라 파일로 주고받는다.** WSL2 는 NAT 라 WSL→Windows 의 localhost 가 통하지 않는다.
프로젝트 폴더는 Windows·WSL 양쪽에서 같은 위치를 보므로 그곳을 교환 지점으로 쓴다.

```
<project>/.agent-workspace/approvals/<sessionId>/
   <id>.req.json   ← hook 이 기록 (앱이 200ms 폴링)
   <id>.res.json   ← 앱이 기록 (hook 이 대기)
```

양쪽 다 `.tmp` → rename 으로 원자적 기록해 부분 읽기를 막는다.

```
CLI ──PreToolUse hook──▶ approve.sh / approve.ps1
                              │ .req.json 기록 후 폴링 대기
                              ▼
                        ApprovalBroker ──▶ Renderer (Rail · 대화 · 상태바)
                              │
                 ┌────────────┴────────────┐
             사용자 응답              280초 경과
                 │                         │
          .res.json 기록          hook 이 보류 사유로 deny
                                           │
                                  Inbox 에 `pending` 유지
```

만료 시 deny 사유 문구 (실측에서 모델이 지시를 따름을 확인):

> "사용자 응답 대기 시간 초과. 이 작업은 보류되었습니다. 세션을 종료하지 말고, 다른 진행 가능한 작업을 하거나 사용자 지시를 기다리세요."

세션이 이미 종료된 경우 resume 후 재지시.

### 사전 권한 정책 매핑

| 작업 | 정책 | 구현 |
|---|---|---|
| Read / Glob / Grep | 자동 허용 | hook matcher 에서 제외 → 아예 안 거침 |
| Write / Edit | 질문 (위험도 med, 프로젝트 밖이면 high) | `assessRisk()` |
| Bash / PowerShell | 항상 질문 (위험도 high) | `assessRisk()` |

## 5. 대화 / Artifact 분리 구현

### 출처별 처리

| 출처 | 처리 |
|---|---|
| tool_use / tool_result | 파싱 없이 확정 Artifact |
| assistant 텍스트 델타 | 코드 펜스 상태머신 |

### 코드 펜스 분리

CLI 가 **완성된 메시지 단위**로 주므로(델타 아님) 줄 단위 파서로 충분하다. `renderer/lib/fences.ts`.

| 조건 | 처리 |
|---|---|
| 6줄 이상 코드블록 | Artifact 로 분리, 대화엔 참조 카드(제목·줄 수) |
| 5줄 이하 | 대화에 유지 (shiki 하이라이팅) |
| 인라인 코드 | 대화 유지 |
| `` ```ts:src/a.ts `` | 언어 + 파일 경로 파싱 |
| 닫히지 않은 펜스 | 원문 그대로 살림 |

**원문은 DB 에 그대로 저장하고 분리는 렌더링 시점에만 한다.** 임계값을 바꾸면 과거 대화도 새 기준으로 다시 그려진다.

## 6. Memory / Skills 파일 매핑

Memory는 CLI 정본 파일을 앱이 직접 편집하며 변환·주입하지 않는다. Skills는 공통
`SKILL.md` 정본을 직접 편집하되 provider별 탐색 위치 차이를 피하기 위해 세션에 카탈로그를 연결한다.

| 계층 | Claude | Codex |
|---|---|---|
| Global Memory | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` (확인 필요) |
| Project Memory | `<project>/CLAUDE.md` | `<project>/AGENTS.md` |
| Agent Memory | `<project>/.claude/agents/<name>.md` 본문 | — |
| Global Skills | `<userData>/skills/global/<name>/SKILL.md` 정본을 세션 카탈로그로 연결 | 동일 |
| Project Skills | `<project>/.agents/skills/<name>/SKILL.md` 정본을 세션 카탈로그로 연결 | 동일 |
| Agent Skills | `<userData>/skills/agents/<agent>/<name>/SKILL.md` 및 Agent별 상태 | 동일 |

Memory에서 주입 방식을 배제한 이유: 임시 파일 생성·정리 부담, 크래시 시 잔여물, 사용자 원본과의 충돌,
git status 오염, 앱 밖 CLI 실행 시 미적용(진실 이중화). Skills는 임시 복제본을 만들지 않고 정본의
설명·경로만 연결하며, Required 본문만 명시적으로 세션 지침에 포함한다.

### 변경 이력 (DB)

| 컬럼 | |
|---|---|
| scope | global / project / agent |
| target_path | 실제 파일 경로 |
| author | user / ai |
| proposed_by_session | 제안 세션 ID |
| source | 근거 |
| approved | 승인 여부 |
| diff | 변경분 |
| created_at / updated_at | |

파일은 정본 하나, 이력은 DB.

## 7. 에이전트 저장 형식

에이전트는 **앱이 전역으로 관리**한다. 프로젝트마다 흩어두지 않는다.

```
<userData>/agents/<name>.md
```

파일 형식은 Claude Code 표준 프론트매터 그대로다. 내보내면 그 자리에서 바로 동작한다.

```yaml
---
name: refactor-agent
description: 리팩터링 전담. 기능 변경 없이 구조만 정리한다.
model: opus
x-workspace:                       # 앱 전용 설정. 표준 필드를 건드리지 않게 분리한다.
  projects: ['D:\work\api']        # 적용 대상. 비우면 전체 프로젝트.
  allowedTools: [Read, Edit]
  completion: 테스트 통과 후 변경 요약 보고
---

(본문 = 역할 지침)
```

### 실행은 파일 배치가 아니라 인라인 정의로

```
--agents '{"<name>": {"description": ..., "prompt": ..., "model": ...}}'
--agent  <name>
```

- 러너마다 홈 디렉터리가 다르다(WSL `~/.claude` ≠ Windows `%USERPROFILE%\.claude`).
  파일을 배치하는 방식이면 러너를 바꿀 때마다 동기화해야 한다. 인라인 정의는 그 문제가 없다.
- 프로젝트의 `.claude/` 를 앱이 오염시키지 않는다.
- 사용자 지시와 공통 시스템 지침은 **stdin으로 전달**한다. Windows→WSL argv에는 실행 옵션만
  남겨 긴 Memory·Skill 지침도 `spawn ENAMETOOLONG` 없이 전달한다.

### 프로젝트 파일과의 관계

- 프로젝트의 `.claude/agents/*.md` 는 **가져오기 후보로만** 읽는다(`scanProject`).
- 가져오면 라이브러리로 **이동**한다. 같은 이름이 두 곳에 남으면 어느 쪽이 정본인지 알 수 없다.
- 반대로 **내보내기**로 프로젝트에 파일을 떨궈두면 앱 없이 `claude --agent` 로 쓸 수 있다.

## 7-1. 홈 지시 라우팅

홈(Overview)에서 받은 지시를 어느 프로젝트의 어느 Agent 에게 보낼지 정한다. `main/router.ts`.

```
지시 입력
  → 라이브러리의 에이전트 수집
  → 후보 0개  : 안내만
    후보 1개  : 모델 호출 없이 그대로 선택
    후보 2개~ : haiku 1회 호출로 선택
  → 확인 카드 (제안 + 이유 + 실행할 프로젝트 선택)
  → [실행] 눌러야 세션 시작 (--agent)
```

- 라우터 모델은 `claude-haiku-4-5` 로 **고정**한다. 목록을 보고 하나 고르는 일에
  상위 모델을 쓸 이유가 없다. 판단 1회는 대략 opus 대비 1/10 수준이다.
- 라우터에게는 **도구를 주지 않는다** (`--disallowedTools`). 도구를 쓰면 승인 요청이
  뜨는데, 홈에는 승인 UI 흐름이 없어 그대로 멈춘다.
- 응답은 `--output-format json` 의 `result` 안에 자유 텍스트로 온다. 코드 펜스나 인사말이
  섞여 오므로 정규식으로 JSON 객체만 건져 파싱한다.
- **적합한 후보가 없으면 `index: 0`** 을 허용한다. 억지로 고르게 하면 엉뚱한 프로젝트에서
  세션이 시작된다.
- 라우팅 결과는 절대 자동 실행하지 않는다. 실행 대상 프로젝트가 바뀌는 동작이라
  사용자 확인을 반드시 거친다.
- **실행 환경을 여기서 임의로 정하지 않는다.** 대상 프로젝트에 러너가 없으면 일반 세션과
  똑같이 첫 지시 시점에 사용자가 고르게 한다(§11-1). 홈에서 왔다는 이유로 규칙이 달라지면 안 된다.
- `selectProject()` 직후에는 `active` 상태가 아직 반영되지 않는다. 프로젝트 경로를 인자로 넘긴다.

## 7-1-1. 실행 환경 제한 (데이터 경계)

에이전트 지침은 **전문이 그대로 모델에 실려 나간다**(`--agents` 인라인). 내부 도메인 지식이
든 에이전트를 다른 provider 로 돌리면 그 순간 전부 외부로 나간다.

`x-workspace.providers` 로 돌릴 수 있는 provider 를 못박는다. 비우면 제한 없음.

```yaml
x-workspace:
  providers:
    - claude-cli      # 이 에이전트는 Claude 로만
```

- 화면에서도 거르지만 **`session-manager.start()` 에서 한 번 더 막는다.**
  UI 필터만 두면 커맨드 팔레트·홈 라우팅 같은 다른 진입로로 새어 나간다.
  막힌 경우 세션을 시작하지 않고 `failed` 상태와 사유를 남긴다.
- 도메인 지식이 든 에이전트는 특정 provider 로 고정해 두고 쓴다.

## 7-2. 에이전트 가져오기

**가져오기는 다운로드가 아니라 검토다.** 남이 쓴 지침은 그 자체가 실행 지시이고,
`allowedTools` 에 `Bash` 가 들어 있으면 받는 순간 그대로 돈다.

```
URL 또는 파일
  → 파싱만 한다 (저장하지 않는다)
  → 검토 화면: 지침 전문 + 요구 권한 + 위험 문구 표시
  → 사용자가 권한을 직접 켜고 이름·적용 대상을 정한다
  → 그때 저장
```

- **요구한 권한을 기본값으로 켜주지 않는다.** 무엇을 요구했는지만 보여주고 전부 꺼둔 채 시작한다.
  적용 대상도 비운 채로 둔다 — 받자마자 전 프로젝트에서 도는 일이 없어야 한다.
- `https` 만 받는다. GitHub·GitLab 의 브라우저 주소는 raw 주소로 바꿔 읽는다
  (사용자는 주소창을 복사할 뿐 raw 링크를 찾아오지 않는다).
- 지침 본문에서 `rm -rf`·`curl`·`git push --force`·자격증명 언급·`sudo` 를 찾아 배너로 알린다.
  **차단이 아니라 주의 환기다** — 어디를 봐야 하는지 알려줄 뿐 판단은 사용자가 한다.
- 512KB 상한. 응답 크기를 안 보면 UI 가 멈춘다.
- ⚠ TLS 검사 프록시 뒤에서는 외부 `fetch` 가 막힐 수 있다. 그때는 **파일에서 가져오기**가 대안이다.

### Linked — 원본과 연결해 두기

URL 로 가져온 경우에만 연결할 수 있다(로컬 파일은 다시 읽을 보장이 없다).
`x-workspace.source` 에 `{ url, hash, checkedAt }` 를 남긴다.

```
[업데이트 확인]  ← 사용자가 누를 때만 확인한다
  → 원본 다시 받아 해시 비교
  → 바뀌었으면 카드에 배지
  → 변경분(unified diff) + 새로 요구한 도구 표시
  → [적용]
```

- **확인은 자동으로 하지 않는다.** 화면을 열 때마다 외부로 요청을 보내면
  네트워크에서 조용히 느려지고, 사용자가 의도하지 않은 트래픽이 된다.
- 적용해도 **권한(`allowedTools`)과 적용 대상(`projects`)은 로컬 값을 유지한다.**
  원본이 도구를 더 요구하도록 바뀌었으면 그 사실만 알리고 켜는 것은 사용자가 한다.
  자동으로 켜주면 가져올 때 권한을 다시 정하게 한 의미가 사라진다.
- 모델도 로컬 값을 유지한다(바뀐 사실만 표시).
- 변경 감지는 원본 **전문의 sha256 앞 16자**로 한다. 파싱 결과가 아니라 원문 기준이라
  주석·공백 변경도 잡힌다.
- diff 는 줄 단위 LCS 로 직접 만든다(`lib/diff.ts`). 지침은 길어야 수백 줄이라 O(nm) 로 충분하다.

## 7-4. Memory

**CLI 가 실제로 읽는 파일이 정본이다**(기획서 11장). 앱이 별도 저장소를 두고 세션 시작 시
주입하지 않는다 — 앱 밖에서 CLI 를 직접 실행해도 똑같이 적용돼야 한다.

| 계층 | 위치 | 읽는 CLI |
|---|---|---|
| 전역 | `<러너 홈>/.claude/CLAUDE.md` | Claude 전용 |
| 프로젝트 | `<프로젝트>/AGENTS.md` (+ `CLAUDE.md` = `@AGENTS.md`) | 모든 CLI |
| **자동 메모리** | `<러너 홈>/.claude/projects/<cwd 인코딩>/memory/*.md` | Claude 전용 |
| 에이전트 | 라이브러리 파일의 `x-workspace.memory` | 모든 CLI (앱이 프롬프트에 붙임) |

### 비용 표시 — 없는 값을 지어내지 않는다

Claude 는 `total_cost_usd` 를 주지만 **Codex 는 토큰만 준다.** 단가표를 앱에 박아 환산하면
모델이 바뀌거나 요금이 바뀔 때 조용히 틀린 숫자를 보여주게 된다.
그래서 **비용이 오면 비용을, 없으면 토큰 수를 그대로** 보여준다.

### 도구 이식성 — 실측

| 조건 | Claude Code 가 읽나 |
|---|---|
| `AGENTS.md` 만 있음 | **아니오** |
| `CLAUDE.md` 만 있음 | 예 |
| `CLAUDE.md` 가 `@AGENTS.md` 한 줄 | **예** (임포트를 따라감) |

그래서 **프로젝트 메모리는 `AGENTS.md` 를 정본**으로 쓰고, `CLAUDE.md` 는 `@AGENTS.md`
한 줄짜리 다리로만 둔다. 원본은 하나인데 Claude 와 다른 CLI 가 같은 파일을 읽는다.
저장할 때 `CLAUDE.md` 가 없으면 자동으로 만들어 주고, 이미 다른 내용이 있으면
**건드리지 않고 경고만** 한다(사용자가 쓴 것을 앱이 덮으면 안 된다).

전역과 자동 메모리는 `.claude` 아래라 이식할 방법이 없다. 화면에 「Claude 전용」으로 표시한다.

**자동 메모리를 빠뜨리면 안 된다.** 평소 쌓이는 건 `CLAUDE.md` 가 아니라 이쪽이다
(이 PC 한 경로에만 118개). `MEMORY.md` 색인 + 사실 하나당 파일 하나 구조다.

- 디렉터리 이름은 cwd 를 `[^a-zA-Z0-9] → -` 로 바꾼 것이라 **되돌릴 수 없다**
  (한글 경로가 통째로 `-` 가 된다: `프로젝트-개인` → `---------`).
  그래서 이름을 해독하지 말고 **세션 기록(`*.jsonl`) 첫머리의 `cwd` 를 읽어** 실제 경로를 얻는다.
- 등록된 프로젝트와 1:1 이 아니다. 앱에 등록 안 된 경로의 메모리도 그대로 보여준다 —
  실제로 쓰는 것이 거기 있기 때문이다.
- 목록에는 **내용을 싣지 않는다.** 100개가 넘어 매번 읽으면 낭비다. 고른 항목만 따로 읽는다.

- **전역은 러너마다 홈이 다르다.** WSL 의 `~` 와 Windows 의 `%USERPROFILE%` 는 별개 파일이라
  한쪽을 고쳐도 다른 쪽 세션에는 적용되지 않는다. 그래서 **러너별로 따로 보여준다**
  (「전역 · WSL Ubuntu」 / 「전역 · Windows」). 하나로 합쳐 보여주면 반드시 오해가 생긴다.
- WSL 홈은 Windows 에서 `\\wsl.localhost\<배포판>\home\<user>` UNC 로 읽고 쓴다.
  경로는 탐지 시 `wsl -d X -- sh -c 'echo $HOME'` 로 알아내 러너에 담아둔다.
- WSL 이 꺼져 있으면 UNC 접근이 실패한다 → 「없음」으로 표시할 뿐 오류로 막지 않는다.
- 에이전트 메모리는 `--agents` 프롬프트에 `## 기억해 둘 것` 절로 붙는다.
  지침이 *역할*이라면 메모리는 *그 역할이 기억할 것들*이다.
- 변경 이력은 파일이 아니라 앱 DB(`memory_edit`)에 남긴다. 파일은 CLI 의 것이므로 오염시키지 않는다.

## 7-5. Checkpoint

세션을 그대로 이어갈 수 없을 때 작업 상태를 넘긴다(기획서 17장). `main/checkpoint.ts`.

**Resume 과의 차이: 세션 ID 가 아니라 텍스트를 넘긴다.** 세션 기록은 러너 홈마다 따로라
ID 는 경계를 못 넘는다. 텍스트면 Claude→Codex, WSL→Windows, 에이전트 A→B 가
전부 같은 경로로 풀린다. 그래서 인계 창에서 **실행 환경과 에이전트를 새로 고르게** 한다.

담는 것: 지시 목록 · 직전 보고 · 바뀐 파일(Git 스냅샷 기준) · 산출물 · 실패한 작업.
**전체 대화는 넣지 않는다** — 새 세션의 컨텍스트만 잡아먹는다.

- 본문은 **앱이 아는 사실만** 조립한다. 「남은 일」은 비워 두고 사용자가 채운다.
  앱이 지어내면 틀린 인계가 되고, 받는 쪽은 그게 틀렸는지 알 방법이 없다.
- 저장 전 편집 가능하게 둔다. 인계 품질은 사람이 마지막에 손대야 올라간다.
- 고른 실행 환경에서 못 쓰는 에이전트는 목록에서 빠진다(provider 가드와 같은 규칙).

## 7-6. Worktree 격리 실행

여러 세션이 같은 작업 디렉토리를 공유하면 서로의 편집을 덮어쓴다. 지금까지는
감지해서 경고만 했는데(`checkConflict`), worktree 로 나누면 애초에 부딪히지 않는다.
새 세션은 별도 설정 없이 worktree에서 시작한다. Git 저장소가 아니거나 자동 생성에
실패한 경우에만 원본 프로젝트에서 직접 실행한다.

```
git worktree add -b puppeteer/<세션8자> <userData>/worktrees/<세션id> HEAD
```

- **저장소 밖(앱 데이터 폴더)에 만든다.** 저장소 안에 두면 프로젝트마다 `.gitignore` 를
  손봐야 하고 사용자 파일 목록을 오염시킨다.
- 새 브랜치를 파므로 원래 브랜치는 건드리지 않는다. 기준은 현재 `HEAD`.
- 원본 폴더의 미커밋 변경은 새 worktree에 복사되지 않는다. 이런 파일이 있으면 세션에
  경고를 남겨 기준 커밋과 로컬 변경을 혼동하지 않게 한다.
- 세션의 `cwd`·승인 디렉터리·Git 스냅샷·변경 조회·diff 가 모두 worktree 기준이 된다.
- **만들지 못해도 세션은 진행한다.** git 저장소가 아닐 수 있고, 격리 실패로 작업 자체를
  막을 이유는 없다. 대신 현재 폴더로 전환했다는 경고를 대화에 남긴다.
- 이어가는 턴은 이미 만든 worktree를 그대로 쓴다. 과거에 현재 폴더에서 시작한 세션도
  중간에 worktree를 새로 만들지 않아 CLI resume의 작업 경로를 유지한다.
- 사용자가 worktree를 정리하면 상단에 `Worktree 정리됨` 상태가 남는다. 이 세션에 다시
  지시하면 현재 원본 `HEAD`에서 고유한 새 브랜치와 worktree를 자동 생성한다. 이전 버전에서
  이미 정리한 세션은 저장된 `격리 실행` 이벤트를 기준으로 이 상태를 한 번 복구한다.

### 원본 브랜치에 병합

worktree 생성 시 원본 브랜치와 기준 커밋을 함께 기록한다. 세션 상단의 브랜치 버튼에서
기준 커밋 이후 전체 diff 를 보고, 미커밋 변경을 커밋하고, 원본·worktree 폴더를 열고,
병합 가능 상태를 확인할 수 있다.

프로젝트별 작업 방식은 `사용 안 함`, `자동 병합`, `병합 제안`이며 기존 프로젝트의 안전한
기본값은 병합 제안이다. 설정 화면의 값은 앞으로 등록할 프로젝트의 기본값으로만 사용한다.
자동 병합은 정상 완료 시 worktree의 변경을 `git add -A`로 커밋한 뒤, 다음 조건을 모두
만족할 때 `git merge --ff-only <작업브랜치>` 로 실행한다.

- 세션 실행이 끝남
- 자동 커밋 이후 worktree가 깨끗하고 원본 프로젝트에 커밋되지 않은 변경이 없음
- 원본 프로젝트가 생성 당시 브랜치에 있음
- 작업 브랜치가 원본 브랜치와 갈라지지 않아 fast-forward 가능

병합 제안 모드이거나 자동 처리의 안전 조건을 만족하지 않으면 원본 저장소를 더 바꾸지 않고,
세션 대화에 worktree의 `cd` 경로와 프로젝트 실행 명령, 수동 병합 안내를 남긴다.
Worktree 관리 화면에는 마지막 자동 반영 단계와 결과를 한 줄로 표시한다. 상세 영역을 펼치면
마지막 확인 시각, worktree 경로, dirty·ahead·behind·fast-forward 가능 여부와 실패 원인을
볼 수 있으며, 상태 확인·커밋·병합 중일 때만 짧게 폴링한다.
완료된 세션에 미반영 작업이 있지만 진단 기록이 없으면 Worktree 상태 조회 시 한 번 복구 실행한다.
상태 확인·커밋·병합 중 기록이 30초 넘게 갱신되지 않았으면 앱 종료 등으로 중단된 것으로 보고
Worktree 화면을 열 때 현재 Git 상태부터 다시 확인한다.
진단 DB 저장 실패는 본래의 커밋·병합을 중단시키지 않는다.
앱이 원본 브랜치를 자동
전환하지 않으며, 병합 후에도 worktree와 작업 브랜치는 자동 삭제하지 않는다.
아직 작업 브랜치에 커밋이 없으면 `원본에 반영됨`이 아니라 `반영할 커밋 없음`으로 표시한다.
worktree 에 미커밋 변경이 있으면 관리 화면에서 메시지를 입력해 `git add -A` 후 커밋할 수 있다.
원본 브랜치가 다른 세션 병합으로 앞서가면 관리 화면에서 worktree 브랜치를 최신 원본 위로
재배치할 수 있다. 재배치 중 충돌이 나면 전용 worktree의 rebase를 멈춘 상태로 두고, Git의
현재 충돌 stage를 전용 새 창에 원본/worktree 좌우 비교로 표시한다. 모든 변경 블록을 확인해야
적용할 수 있고, 다음 커밋에서 다시 충돌하면 같은 창에서 이어서 해결한다. 삭제 충돌은 파일 유지와
삭제 중 하나를, 바이너리 충돌은 파일 전체에서 사용할 쪽을 선택한다. 해결 창을 닫으면 rebase를
자동 abort해 worktree를 이전 상태로 되돌리고, 성공하면 관리 화면 상태와 병합 버튼을 갱신한다.

### 정리

세션을 지울 때 worktree도 함께 정리한다. 단, **미커밋 변경이나 원본에 병합하지 않은 커밋이
있으면 세션 삭제 자체를 중단한다.** 폴더만 남기고 앱의 세션 연결을 잃는 상태를 만들지 않기
위해서다. 작업을 커밋·병합하거나 Worktree 관리에서 명시적으로 정리한 뒤 삭제할 수 있다.

Worktree 관리에서 정리할 때는 실행 중인 세션을 먼저 차단하고, Git이 반환한 실제 실패 사유를
화면에 표시한다. 폴더 정리가 끝나면 `git branch -d`로 안전하게 삭제 가능한 작업 브랜치도
함께 정리한다. 미병합 커밋이 있는 브랜치는 강제 삭제하지 않고 보존한다.

## 13. UI 규칙

디자인을 이어서 만질 때 지킬 기준.

### 테마

Catppuccin **Mocha**(다크) / **Latte**(라이트). 색은 전부 CSS 변수(`--color-*`)로 두고
`:root[data-theme='light']` 에서 값만 교체한다. 컴포넌트는 테마를 몰라도 된다.

> Latte 원본은 문서용 팔레트라 UI 에서 경계선·보조 텍스트가 흐리다.
> `surface` / `overlay` 계열을 한 단계씩 진하게 조정해 쓴다.

shiki 도 두 테마를 함께 로드해 현재 테마로 다시 그린다.

### 폰트

**Pretendard 가변 폰트를 파일로 번들에 넣는다.** `src/renderer/src/assets/fonts/`.

- 렌더러 CSP 가 외부 요청을 막으므로 웹폰트 CDN 은 애초에 못 쓴다.
  쓸 수 있더라도 네트워크가 막히면 글꼴이 통째로 바뀐다.
- 가변 하나(2MB)로 45~920 전 굵기를 덮는다. 굵기별 정적 파일보다 작고 관리도 쉽다.
- `format('woff2-variations')` 는 **폐기된 표기다.** 최신 Chrome 이 `@font-face` 를
  통째로 건너뛰어 조용히 시스템 폰트로 떨어진다. 가변이어도 `format('woff2')` 가 맞다.
- 로드 실패를 콘솔에 남긴다(`document.fonts.check`). 폰트는 안 떠도 화면이 멀쩡해 보여서
  틀어진 걸 눈치채기 어렵다.
- 한글은 `letter-spacing: -0.01em` 을 줘야 라틴과 균형이 맞는다.

### 글씨 계층

| 크기 | 용도 |
|---|---|
| 16px | 화면 제목 |
| 14px | 대화 본문 · 입력 · 프로젝트명 |
| 13px | 세션 탭 · 코드 · 목록 · 표 |
| 12px | 보조 설명 · 도구 칩 · 버튼 |
| 11px | 섹션 라벨 · 뱃지 · 경로 · 시각 · 줄 수 |

11px 는 **읽지 않아도 되는 부가 정보**에만 쓴다. 최소 크기다.

### 구분선

기본은 **배경 대비**(`crust` < `mantle` < `base` < `surface0`)로 구분하고, 선은 아래에만 쓴다.

| 선을 쓰는 곳 | 이유 |
|---|---|
| 레일 ↔ 본문 ↔ Artifact 패널 | 3분할 구조 |
| Artifact 패널 내부 | 정보 밀도가 높아 배경만으로 부족 |
| 승인 · 충돌 · 로그인 · 에러 카드 | 경고는 눈에 띄어야 함 |
| 입력창 | 입력 가능 어포던스 |
| 모달 외곽 | 떠 있는 레이어 |

대화 영역은 선을 쓰지 않는다. 읽는 영역이라 여백이 낫다.

### 실행 환경은 세션마다, 시작 후에는 잠근다

러너는 **세션 단위**로 정한다(`session.runner_id`). 프로젝트 러너는 새 세션의 기본값일 뿐이다.
한 프로젝트에서 탭 하나는 Claude, 다른 탭은 Codex 로 돌릴 수 있다.

**세션이 시작되면 못 바꾼다.** 세션 기록이 러너 홈마다 따로 있어

```
WSL     ~/.claude/projects/          194
Windows %USERPROFILE%\.claude\       38
Codex   ~/.codex/sessions/             7
```

바꾸는 순간 `--resume` 이 통하지 않는다. 바꿀 수 있게 두고 경고하는 것보다
**아예 잠그고 새 세션을 열게** 하는 편이 낫다 — 경고는 읽히지 않는다.
`run()` 에도 러너 불일치 시 resume 을 끊는 방어를 남겨 둔다.

### 모달

배경 흐림은 **2px 까지만.** 그 이상은 뒤 내용이 뭉개져 맥락이 끊긴다.
어둡기(`bg-crust/60`)로 초점을 만들고 흐림은 거들기만 한다.

### 설정

전역 토글(테마·알림)은 **레일 상단 이름 옆 설정 버튼** 한곳에 모은다.
화면 구석마다 흩어두면 어디에 뭐가 있는지 기억해야 한다.
설정 창에는 읽기 전용으로 탐지된 실행 환경 목록과 앱 업데이트 상태도 함께 보여준다 — 달리 볼 곳이 없다.
설치본은 시작 뒤 업데이트를 확인하지만 자동 다운로드하지 않는다. 새 버전 표시, 릴리스 노트,
다운로드, 재시작 설치를 사용자가 명시적으로 선택한다.

### 레이아웃

```
┌────────┬──────────────────────┬─────────┐
│  Rail  │  Session Tabs        │ (탭바)  │
│        ├──────────────────────┼─────────┤
│ 프로젝트│  Conversation        │Artifacts│
│ 승인   │                      │ (접기)  │
│ 실행중 ├──────────────────────┤         │
│ 사용량 │  Prompt              │         │
└────────┴──────────────────────┴─────────┘
```

- 그리드 배치는 `col-start` / `row-start` 로 **명시**한다. 탭 바가 조건부로 사라질 때
  자동 배치가 어긋난다.
- 상단 가로 헤더는 두지 않는다. 프로젝트명은 레일에 이미 있다.
- 대화 상단 페이드는 **스크롤됐을 때만** 띄운다. 항상 띄우면 첫 메시지를 가린다.
- **폼은 라벨 | 컨트롤 2단**으로 짠다. 라벨을 위에 쌓으면 세로가 두 배가 되고 위계가 평평해진다.
- **보조 설명은 상시 노출하지 않는다.** 라벨 옆 `?` 에 넣고 hover·focus 에서만 띄운다.
  옆에 회색 글씨로 늘어놓으면 라벨과 경쟁해서 정작 라벨이 안 읽힌다.
- 모달에 **머리·바닥 회색 바를 두지 않는다.** 여백으로 구분한다. 입력도 테두리 대신
  채움(`bg-base`) + 포커스 링만 쓴다. 테두리를 두르면 필드 개수만큼 선이 늘어난다.
- **파괴적 동작은 같은 자리에서 두 단계로** 받는다(삭제 → "삭제할까요?"). 별도 모달을 겹치지 않는다.
- **새 세션 버튼은 탭바 맨 왼쪽에 고정**한다. 오른쪽에 두면 탭 개수에 따라 자리가 움직인다.
- 탭바 안의 버튼에 `mb-px` 같은 세로 오프셋을 주지 않는다. 활성 배경(`base`)이 1px 들리면
  뒤의 바 배경(`mantle`)이 회색 줄로 비친다. 테두리처럼 보이지만 테두리가 아니다.
- **세션 탭바에 가로 스크롤을 두지 않는다.** 탭은 남는 폭을 나눠 쓰다가(최대 220px),
  한 탭이 116px보다 좁아질 상황이면 나머지를 넘침 목록(`⌄ N`)으로 뺀다.
  활성 세션은 넘침 대상이어도 탭으로 끌어올린다 — 지금 보는 것이 안 보이면 안 된다.
  가용 폭은 창 크기·Artifact 패널 폭에 따라 바뀌므로 `ResizeObserver` 로 관찰한다.

### 0.1.0 후보: 멀티 Agent 실행 계층

현재의 멀티 세션은 각 세션이 독립적으로 하나의 Agent 역할을 실행한다. 후속 멀티 Agent는 한 사용자
지시 아래 Lead와 여러 보조 실행을 묶는 별도 오케스트레이션 계층이다.

| 책임 | 초기 정책 |
|---|---|
| 작업 분해·최종 응답 | Lead Agent |
| 병렬 조사 | 보조 Agent 최대 3명 |
| 파일 쓰기 | Lead만 허용, 보조 Agent는 읽기 전용 기본값 |
| 메시지 | 위임 요청과 구조화된 결과 반환. 무제한 Agent 간 자유 대화는 지원하지 않음 |
| provider | Puppeteer가 Claude/Codex 프로세스를 직접 관리해 혼합 구성 가능 |
| 생명주기 | 전체 취소·부분 실패·타임아웃·Lead 종료 시 하위 프로세스와 승인 요청 정리 |
| 관측 | Agent별 상태·실행환경·권한·토큰·오류를 분리 표시 |

구현 전에 기존 `SessionManager`, 승인 브로커, 사용량 집계와 DB 이벤트 모델에서 부모 작업 ID와 하위
실행 ID를 분리하는 스키마를 설계한다. 보조 Agent가 같은 worktree를 동시에 수정하는 방식은 초기
범위에서 제외하며, 필요해질 경우 Agent별 worktree와 명시적 결과 통합 단계로 별도 설계한다.

### Memory 제안 승인

AI의 Project/Agent Memory 제안은 provider 공통 `memory-proposal` 출력 규약으로 받는다.
앱은 제안을 SQLite 대기함에만 기록하고, Memory 화면에서 현재 정본과 diff를 보여준 뒤
사용자 승인 시점의 최신 파일에 추가한다. Global Memory는 기획 원칙대로 제안 대상에서 제외한다.

### Skills 3계층

공통 `SKILL.md` 형식을 Global · Project · Agent 정본으로 관리한다. 같은 이름은
Agent > Project > Global 순으로 해석한다. Agent별 `required`는 본문을 항상 적용하고,
`available`은 설명과 정본 경로를 제공해 필요할 때 읽게 하며, `disabled`는 제외한다.
CLI 홈에 복제하지 않고 세션 단위 지침으로 카탈로그를 연결해 Claude와 Codex의 동작을 맞춘다.

### Agent provider 호환성

Puppeteer Agent를 역할·권한·완료 조건·Memory·연결 Skills를 가진 provider 중립 정본으로 본다.
Claude CLI에서는 `--agents` 인라인 정의로 전달하고, 이를 지원하지 않는 Codex CLI에서는 같은 역할
본문을 세션 프롬프트 앞에 붙인다. Skills는 별도 정본이며 두 provider에 같은 해석 결과를 제공한다.

Claude Agent와 Codex Skill을 동일 타입으로 합치지 않는다. Claude Agent 파일은 역할 프로필로
가져올 수 있지만 Codex `SKILL.md`는 반복 절차이므로 Skill 라이브러리에 가져와 Agent의
Required/Available/Disabled 정책으로 연결하는 것이 목표다. 현재 Agent를 Codex Skill로 내보내는
기능은 역할을 절차 문서로 바꾸는 손실 변환이다. 후속 UI에서는 이를 명시하고, 통합 가져오기 시
원본 형식·매핑 결과·버려지는 필드를 승인 전에 보여줘야 한다.

### 미착수·보류 (v2)

- Claude Agent와 Codex Skill을 하나로 합치는 손실 변환. 각각 Agent·Skill로 가져오는 검토 UI는 지원한다.
- Agent 원본 형식의 provider 전용 확장 필드 보존과 round-trip 검증

**터미널 뷰(PTY)는 이 PC 에서 불가능하다** — node-pty 네이티브 빌드가 막힌다(§15).

## 15. 이 환경에서 밟은 함정

같은 실수를 반복하지 않기 위한 기록. 대부분 프록시 환경·WSL·한글 경로에서 나왔다.

**조용한 폴백을 만들지 않는다.** 문법 강조 실패를 평문으로 넘기던 동안 원인(CSP·WASM)을
알 수 없었다. 실패는 화면에 남겨야 진단이 된다. 아래 두 건은 그렇게 잡혔다.

| 증상 | 원인 | 대응 |
|---|---|---|
| `SELF_SIGNED_CERT_IN_CHAIN` | TLS 검사 프록시가 Electron 헤더 다운로드 차단 | 네이티브 모듈을 쓰지 않는다 → `node:sqlite` |
| `Electron uninstall` | Electron 43+ 는 패키지에 postinstall 이 없어 `npm ci` 만으로는 바이너리를 받지 않음 | 앱 `postinstall`: `install-electron` (수동 실행은 `npx install-electron`) |
| WSL 세션이 인증 실패 | `wsl.exe -- claude` 가 **Windows npm 설치본**을 잡음 (interop PATH) | 탐지된 **절대경로**로 실행 |
| `spawn EINVAL` 또는 프롬프트 따옴표 손상 | Node 보안 수정으로 `.cmd`/`.bat` 직접 spawn 불가하고 단순 `cmd /c`는 인자를 재해석 | `cmd.exe /d /s /c` + Windows 인자별 인용 + 실제 cmd 왕복 회귀 테스트 |
| `npm install --package-lock-only`에서 `install-electron`을 찾지 못함 | package-lock 전용 설치에서도 `postinstall`이 실행되지만 devDependency 실행 파일이 없는 상태 | lockfile만 갱신할 때 `npm install --package-lock-only --ignore-scripts`, 정상 설치는 `npm ci` |
| Windows Git 다중 rebase 테스트가 간헐적으로 5초 초과·`EBUSY` | 프로세스 종료와 임시 디렉터리 잠금 해제가 느림 | 해당 통합 테스트 timeout 확대, 임시 폴더 제거 재시도 |
| 화면이 반응 없이 멈춤 | spawn 동기 throw → IPC 거부를 렌더러가 미처리 | 예외를 `status:'failed'` 이벤트로 변환 + 렌더러 catch |
| 큰 이미지 첨부 실패 | `String.fromCharCode(...arr)` 인자 개수 초과 | 32KB 청크로 나눠 base64 변환 |
| 드래그앤드롭 무반응 | 입력창에만 핸들러 → 자식이 삼키거나 Electron 기본 동작 | **창 전체**에서 수신 + `will-navigate` 차단 |
| Annotation 텍스트 입력 안 됨 | Electron 은 `window.prompt` 미지원 | 캔버스 위 인라인 입력창 |
| cmd.exe 가 한글 경로를 못 찾음 | bash→cmd 인코딩(UTF-8→CP949) | PowerShell `-EncodedCommand` (UTF-16LE base64) |
| Node 에서 한글 경로 깨짐 | `URL.pathname` 퍼센트 인코딩 | `fileURLToPath` |
| CLI 가 3초 지연 후 경고 | stdin 미지정 | `stdio: ['ignore', ...]` |
| diff 색이 안 보임 | 클래스 + 외부 CSS 가 어딘가에서 묻힘 | 줄 배경을 **인라인 스타일**로 직접 지정 |
| Codex 훅이 조용히 안 걸림 | `hooks_file` 은 **없는 설정 키**다. 오타 아닌 창작이라 경고도 안 난다 | `-c 'hooks.PreToolUse=[…]'` 인라인 TOML (실측) |
| 문법 강조가 조용히 평문으로 폴백 | shiki 기본 oniguruma 엔진이 **WASM** 을 쓰는데 렌더러 CSP(`script-src 'self'`)가 차단 | CSP 를 풀지 않고 `createJavaScriptRegexEngine({forgiving:true})` 로 교체 |
| 코드 블록이 한 줄씩 띄어 보임 | shiki 는 줄 span 사이에 **개행 문자**를 넣는다. `.line{display:block}` 을 주면 블록 줄바꿈 + 개행 = 두 줄 | `code{white-space:normal}` 로 개행을 접고 `.line{white-space:pre}` 로 줄 안 공백만 보존 |
| 후속 지시마다 세션 탭이 늘어남 | `start()` 가 매번 `randomUUID()` 로 새 세션 행을 만듦. CLI 는 `--resume` 해도 새 세션 id 를 준다 | `continueSessionId` 로 기존 행에 이벤트를 이어 쌓는다 (제목·스냅샷 유지) |
| 승인 폴링 타이머 중복 | 같은 세션에 `broker.attach()` 재호출 → 타이머 하나 더 + 세션 허용 초기화 | attach 를 멱등하게 (이미 있으면 dir 만 갱신) |
| macOS 에서 Electron 실행 회귀를 늦게 발견 | 단위 테스트만으로는 앱 부팅 실패를 못 잡음 | `npm run smoke` 로 빌드 산출물을 실제 Electron으로 실행 |

### 개발 환경 메모

- 파일 편집은 WSL 에서, `npm` / `electron` 실행은 Windows 에서 한다.
- WSL 에서 Windows 명령을 돌릴 때는 PowerShell `-EncodedCommand` 를 쓴다.
  프로젝트 경로에 한글이 있어 `cmd.exe` 직접 호출은 실패한다.
