제품 정의와 기능 명세는 `기획서.md` 참조. 이 문서는 구현 방식만 다룬다.

## 1. 확정 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 셸 | Electron + electron-vite | 메인 프로세스가 Node → 프로세스 제어·git·SQLite 직결 |
| UI | React + TypeScript + Tailwind + shadcn/ui | |

| Artifact 뷰어 | **shiki** | 읽기 전용 뷰어에 Monaco(에디터, 5MB+·웹워커)는 과함. 문법강조·줄번호·diff 모두 커버하고 **Catppuccin 테마를 기본 제공** |

| 이미지 Annotation | react-konva | 사각형·화살표·번호·텍스트 → PNG export (미착수) |
| Git / Worktree | simple-git + raw `git worktree` 명령 | worktree는 simple-git 커버 미흡 (미착수) |
| 파일 감시 | chokidar | (미착수) |
| DB | **`node:sqlite`** (Node 24 내장) | 아래 참조 |
| Command Palette | 자체 구현 | 의존성 없이 필터+키보드 이동만 필요 |

> **DB 선택 변경.** 원래 `better-sqlite3` + Drizzle 이었으나 이 환경에서 리빌드가 불가능했다.
> TLS 검사 프록시 뒤에서는 Electron 헤더 다운로드가 `SELF_SIGNED_CERT_IN_CHAIN` 으로 막히고,
> C++ 빌드 도구도 없다. Electron 43 이 Node 24 를 쓰므로 **`node:sqlite` 가 내장**되어 있어
> 네이티브 빌드·다운로드·컴파일러가 전혀 필요 없다. 스키마는 `src/main/db.ts` 에 직접 작성한다.

## 2. 프로세스 모델

```
Electron Main
 ├ SessionManager        세션 생명주기, DB 적재, 렌더러 중계
 ├ ClaudeCliAdapter ×N   CLI 프로세스 1개당 1 인스턴스
 ├ ApprovalBroker        승인 요청 파일 감시 + 응답 기록
 ├ db (node:sqlite)      project / session / event / approval
 └ runner-detect         Windows·WSL 실행 환경 탐지

Renderer (React)
 └ Rail(프로젝트·세션·승인·실행중) · 대화 · Artifact 패널 · Command Palette
```

이벤트는 `sessionId` 로 라우팅되어 렌더러가 세션별 상태를 따로 쌓는다. 화면에 보이지 않는 세션도 백그라운드에서 계속 진행된다.

## 3. CLI Adapter

두 축을 분리한다.

```
Session = Provider × Runner

Provider (무엇)              Runner (어디서)
├ claude-agent-sdk           ├ windows-native  → claude.exe
├ claude-cli                 ├ wsl             → wsl.exe -d <distro> -- claude
└ codex-cli                  └ custom          → 사용자가 명령·인자 직접 지정
```

| Provider | 통신 | 승인 인터셉트 | Resume | 상태 |
|---|---|---|---|---|
| `claude-cli` | spawn + `--output-format stream-json` | hook → HookServer 질의 | `--resume <id>` | **v1 주 경로 (실측 완료)** |
| `claude-agent-sdk` | in-process `query()` | `canUseTool` 콜백 | SDK 세션 ID | v2 선택지 (미검증) |
| `codex-cli` | spawn + JSON 이벤트 스트림 | Codex 프로토콜 정규화 | Codex 세션 ID | v2 |

> **전제 변경.** 초기 설계는 hook 경로의 승인 타임아웃을 이유로 Agent SDK를 주 경로로 삼았다. 스파이크 결과 hook `timeout` 설정이 적용되고 만료 시에도 세션이 죽지 않음을 확인해, **hook 경로를 v1 주 경로로 확정**한다. Agent SDK는 Windows 최적화용 선택지로 격하한다. 근거: `spike/REPORT.md` S2.

### 정규화 이벤트 스키마

세 어댑터가 동일 타입으로 정규화해 올린다. **아래는 Claude CLI 2.1.220 실측 기준.**

```ts
type SessionEvent =
  | { t:'status';   status: SessionStatus }
  | { t:'message';  role:'assistant'|'user'; text:string }
  | { t:'artifact'; kind:'code'|'md'|'diff'|'image'|'log'; path?:string; content:string }
  | { t:'approval'; id:string; tool:string; input:unknown; cwd:string; risk:'low'|'med'|'high' }
  | { t:'file-changed'; path:string }
  | { t:'usage';    inputTokens:number; outputTokens:number; cacheRead:number; costUsd?:number }

type SessionStatus =
  | 'starting' | 'running' | 'waiting-input' | 'approval-required'
  | 'completed' | 'failed' | 'stopped' | 'disconnected' | 'auth-required'
```

### CLI 이벤트 → SessionEvent 매핑 (실측)

| CLI 이벤트 | 추출 | SessionEvent |
|---|---|---|
| `system`/`init` | `session_id`, `cwd`, `model`, `permissionMode`, `tools[]`, `memory_paths`, `claude_code_version`, `apiKeySource` | `status:'running'` + 세션 메타 저장 |
| `rate_limit_event` | `rate_limit_info.status` / `resetsAt` / `rateLimitType` | 상태 바 rate limit 표시 |
| `assistant` (text 블록) | `message.content[].text` | `message` — 코드펜스 파싱 대상 |
| `assistant` (tool_use 블록) | `name`, `input`, `id` | 도구 실행 표시 / 변경파일 추적 |
| `user` (tool_result) | **`tool_use_result.stdout` / `.stderr`** | `artifact` (kind:`log`) — 파싱 불필요 |
| `system`/`thinking_tokens` | | 진행 표시 |
| `result` | `total_cost_usd`, `usage`, `modelUsage` | `usage` — **자체 계산 불필요** |
| `result` | `permission_denials[]` | 승인 거부 이력 → Inbox 반영 |
| `result` | `terminal_reason`, `is_error` | `status:'completed'|'failed'` |

주의: `assistant` 이벤트는 **콘텐츠 블록 단위로 분할되어 오고 같은 `message.id`를 공유**한다. 어댑터에서 `message.id`로 묶는다.

## 4. 승인 구현

### 실측 결과 (`spike/REPORT.md` S2)

| 항목 | 결과 |
|---|---|
| hook `timeout: 300` 설정 | **적용됨** — 20초 지연 hook이 완주 |
| 만료·거부 시 세션 | **죽지 않음** (`is_error:false`, `terminal_reason:completed`) |
| deny 사유 문구 | **모델에게 전달되고 인용됨** → 보류 지시가 실제로 통함 |
| 거부 이력 | `result.permission_denials[]`에 구조화 기록 |

### 설정 주입 — 사용자 파일을 건드리지 않는다

실제 사용자 환경에 **이미 다른 도구가 hook 11종을 `~/.claude/settings.json`에 등록**해 둔 사례를 확인했다. 앱이 이 파일을 편집하면 해당 도구가 깨진다.

→ 앱은 **세션 단위로 `--settings` 인자에 JSON 문자열을 주입**한다. 기존 hook과 공존하며 잔여물이 남지 않는다. 동작 확인 완료.

```
--settings '{"hooks":{"PreToolUse":[{"matcher":"Bash","hooks":[
  {"type":"command","command":"<앱 hook 경로>","timeout":300}]}]}}'
```

사용 가능한 hook 이벤트: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `UserPromptSubmit`, `Stop`, `StopFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `TeammateIdle`, **`PermissionRequest`**

### 4겹 방어

| 순서 | 방법 | 담당 | 상태 |
|---|---|---|---|
| 1 | hook `timeout`을 크게 설정 (300s 이상) | Adapter | 실측 확인 |
| 2 | 사전 권한 정책으로 승인 빈도 축소 | Adapter (hook matcher) | 구현 |
| 3 | Rail·상태바 승인 배지 (OS 알림은 미착수) | Renderer | 구현 |
| 4 | 만료 시 거부 + 보류 복구 | hook 스크립트 | 실측 확인 |

### hook 경로 흐름

**HTTP 가 아니라 파일로 주고받는다.** WSL2 는 NAT 라 WSL→Windows 의 localhost 가 통하지 않는다.
프로젝트 폴더는 Windows·WSL 양쪽에서 같은 위치를 보므로 그곳을 교환 지점으로 쓴다.

```
<project>/.agent-workspace/approvals/<sessionId>/
   <id>.req.json   ← hook 이 기록 (앱이 200ms 폴링)
   <id>.res.json   ← 앱이 기록 (hook 이 대기)
```

양쪽 다 `.tmp` → rename 으로 원자적 기록해 부분 읽기를 막는다.

```
CLI ──PreToolUse hook──▶ approve.sh / approve.ps1
                              │ .req.json 기록 후 폴링 대기
                              ▼
                        ApprovalBroker ──▶ Renderer (Rail · 대화 · 상태바)
                              │
                 ┌────────────┴────────────┐
             사용자 응답              280초 경과
                 │                         │
          .res.json 기록          hook 이 보류 사유로 deny
                                           │
                                  Inbox 에 `pending` 유지
```

만료 시 deny 사유 문구 (실측에서 모델이 지시를 따름을 확인):

> "사용자 응답 대기 시간 초과. 이 작업은 보류되었습니다. 세션을 종료하지 말고, 다른 진행 가능한 작업을 하거나 사용자 지시를 기다리세요."

세션이 이미 종료된 경우 resume 후 재지시.

### 사전 권한 정책 매핑

| 작업 | 정책 | 구현 |
|---|---|---|
| Read / Glob / Grep | 자동 허용 | hook matcher 에서 제외 → 아예 안 거침 |
| Write / Edit | 질문 (위험도 med, 프로젝트 밖이면 high) | `assessRisk()` |
| Bash / PowerShell | 항상 질문 (위험도 high) | `assessRisk()` |

## 5. 대화 / Artifact 분리 구현

### 출처별 처리

| 출처 | 처리 |
|---|---|
| tool_use / tool_result | 파싱 없이 확정 Artifact |
| assistant 텍스트 델타 | 코드 펜스 상태머신 |

### 코드 펜스 분리

CLI 가 **완성된 메시지 단위**로 주므로(델타 아님) 줄 단위 파서로 충분하다. `renderer/lib/fences.ts`.

| 조건 | 처리 |
|---|---|
| 6줄 이상 코드블록 | Artifact 로 분리, 대화엔 참조 카드(제목·줄 수) |
| 5줄 이하 | 대화에 유지 (shiki 하이라이팅) |
| 인라인 코드 | 대화 유지 |
| `` ```ts:src/a.ts `` | 언어 + 파일 경로 파싱 |
| 닫히지 않은 펜스 | 원문 그대로 살림 |

**원문은 DB 에 그대로 저장하고 분리는 렌더링 시점에만 한다.** 임계값을 바꾸면 과거 대화도 새 기준으로 다시 그려진다.

## 6. Memory / Skills 파일 매핑

CLI 정본 파일을 앱이 직접 편집한다. 변환·주입 없음.

| 계층 | Claude | Codex |
|---|---|---|
| Global Memory | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` (확인 필요) |
| Project Memory | `<project>/CLAUDE.md` | `<project>/AGENTS.md` |
| Agent Memory | `<project>/.claude/agents/<name>.md` 본문 | — |
| Global Skills | `~/.claude/skills/` | — |
| Project Skills | `<project>/.claude/skills/` | — |

주입 방식을 배제한 이유: 임시 파일 생성·정리 부담, 크래시 시 잔여물, 사용자 원본과의 충돌, git status 오염, 앱 밖 CLI 실행 시 미적용(진실 이중화).

| target_path | 실제 파일 경로 |

| proposed_by_session | 제안 세션 ID |

| approved | 승인 여부 |
| diff | 변경분 |
| created_at / updated_at | |

파일은 정본 하나, 이력은 DB.

## 7. Project Agent 저장 형식

Claude Code subagent(`.claude/agents/*.md`)와 개념이 겹치므로 자체 포맷을 만들지 않고 frontmatter를 확장한다.

```markdown
---
name: refactor-agent
description: 리팩터링 전담
# --- 앱 확장 필드 ---
x-workspace:
  recommendedCli: claude-agent-sdk
  readPaths:  ["src/**"]
  writePaths: ["src/**"]
  permissions:
    bash: always_ask
    write: auto_in_project
  worktree: prefer
  skills:
    required:  ["ws-grid"]
    available: ["ws-popup"]
    disabled:  []
  completion: "테스트 통과 시 요약 보고"
---

역할 지침 본문 (= Agent Memory)
```

Claude Code에서도 그대로 동작하고, 앱 전용 필드는 무시된다.

### 패키지 import 시 강제 규칙

| 규칙 | 구현 |
|---|---|
| 권한 전부 거부로 시작 | import 시 `permissions` 전 항목을 `deny`로 덮어씀 |
| Bash 고정 | `permissions.bash`를 항상 `always_ask`로 강제 |
| 스크립트 차단 | 패키지 내 실행 파일 존재 시 별도 동의 없으면 import 거부 |
| 비활성 설치 | `enabled: false`로 저장, 첫 실행 전 확인 |

## 7-1. 홈 지시 라우팅

홈(Overview)에서 받은 지시를 어느 프로젝트의 어느 Agent 에게 보낼지 정한다. `main/router.ts`.

```
지시 입력
  → 등록된 전 프로젝트의 .claude/agents/*.md 수집
  → 후보 0개  : 안내만
    후보 1개  : 모델 호출 없이 그대로 선택
    후보 2개~ : haiku 1회 호출로 선택
  → 확인 카드 (제안 + 이유 + 직접 고르기)
  → [실행] 눌러야 세션 시작 (--agent)
```

- 라우터 모델은 `claude-haiku-4-5` 로 **고정**한다. 목록을 보고 하나 고르는 일에
  상위 모델을 쓸 이유가 없다. 판단 1회는 대략 opus 대비 1/10 수준이다.
- 라우터에게는 **도구를 주지 않는다** (`--disallowedTools`). 도구를 쓰면 승인 요청이
  뜨는데, 홈에는 승인 UI 흐름이 없어 그대로 멈춘다.
- 응답은 `--output-format json` 의 `result` 안에 자유 텍스트로 온다. 코드 펜스나 인사말이
  섞여 오므로 정규식으로 JSON 객체만 건져 파싱한다.
- **적합한 후보가 없으면 `index: 0`** 을 허용한다. 억지로 고르게 하면 엉뚱한 프로젝트에서
  세션이 시작된다.
- 라우팅 결과는 절대 자동 실행하지 않는다. 실행 대상 프로젝트가 바뀌는 동작이라
  사용자 확인을 반드시 거친다.
- **실행 환경을 여기서 임의로 정하지 않는다.** 대상 프로젝트에 러너가 없으면 일반 세션과
  똑같이 첫 지시 시점에 사용자가 고르게 한다(§11-1). 홈에서 왔다는 이유로 규칙이 달라지면 안 된다.
- `selectProject()` 직후에는 `active` 상태가 아직 반영되지 않는다. 프로젝트 경로를 인자로 넘긴다.

## 8. 인증 처리

비대화형 모드에서는 로그인 프롬프트가 뜨지 않고 에러로 종료된다.

1. 어댑터가 인증 실패 감지
2. 세션 상태 → `auth-required`
3. UI에 "로그인 필요" + 조치 버튼
4. 버튼 클릭 → **PTY 터미널 창에서 `claude /login` 대화형 실행**
5. 완료 후 세션 재시작 또는 resume

PTY는 터미널 뷰용으로 이미 존재하므로 추가 비용 없음.

## 9. 동시 수정 감지 구현

| 신호 | 처리 |
|---|---|
| 세션 A·B의 Write/Edit tool_use 경로가 겹침 | 충돌 경고 |
| chokidar 변경 감지 + 대응하는 세션 tool_use 없음 | "세션 외부 변경" 라벨만 |

세션별 수정 경로는 `file_change` 테이블에 누적. 파일 워처 단독으로는 경고하지 않는다.

### SQLite (앱 데이터 디렉토리)

| 테이블 | 용도 |

## 11. Windows / WSL 대응

| 항목 | 대응 |
|---|---|
| `node-pty`, `better-sqlite3` 네이티브 모듈 | VS Build Tools + `electron-rebuild`. CI에 버전 고정 |
| WSL 경로 변환 | `wslpath` 계층 (`D:\x` ↔ `/mnt/d/x`) — Runner가 담당 |
| WSL 세션의 첨부 이미지 | Windows 측 저장 후 WSL 경로로 변환해 전달 |
| stdout 인코딩 | WSL spawn 시 UTF-8 / 개행(CRLF) 처리 |
| **WSL interop PATH 오염** ⚠ | `wsl.exe -- claude` 는 WSL 이 뒤에 붙이는 Windows PATH 때문에 **Windows npm 설치본(확장자 없는 래퍼)을 잡을 수 있다.** 그러면 다른 자격증명을 참조해 인증 실패한다. → **항상 탐지된 절대경로로 실행** (`wsl.exe -d <distro> --cd <win경로> -- /home/…/bin/claude …`) |
| wsl.exe stderr 잡음 | 호출마다 `wsl: Failed to mount X:\` 류가 섞여 나온다. `^wsl:\s` 라인은 실패 사유에서 제외 |
| **stdin 리다이렉트** | 미지정 시 CLI가 3초 대기 후 경고. `< /dev/null` 또는 명시적 파이프 **필수** |
| **한글 경로** | Node `URL.pathname`이 퍼센트 인코딩 → **`fileURLToPath` 필수**. 사용자 프로젝트 경로에 한글이 흔하므로 전역 적용 |
| Worktree 경로 길이 | Windows 경로 길이 제한 — worktree 루트를 짧게 |
| Agent SDK + WSL | 미검증. 미지원이면 WSL은 `claude-cli` spawn으로 고정 |

## 13. UI 규칙

디자인을 이어서 만질 때 지킬 기준.

### 테마

Catppuccin **Mocha**(다크) / **Latte**(라이트). 색은 전부 CSS 변수(`--color-*`)로 두고
`:root[data-theme='light']` 에서 값만 교체한다. 컴포넌트는 테마를 몰라도 된다.

> Latte 원본은 문서용 팔레트라 UI 에서 경계선·보조 텍스트가 흐리다.
> `surface` / `overlay` 계열을 한 단계씩 진하게 조정해 쓴다.

shiki 도 두 테마를 함께 로드해 현재 테마로 다시 그린다.

### 글씨 계층

| 크기 | 용도 |
|---|---|
| 16px | 화면 제목 |
| 14px | 대화 본문 · 입력 · 프로젝트명 |
| 13px | 세션 탭 · 코드 · 목록 · 표 |
| 12px | 보조 설명 · 도구 칩 · 버튼 |
| 11px | 섹션 라벨 · 뱃지 · 경로 · 시각 · 줄 수 |

11px 는 **읽지 않아도 되는 부가 정보**에만 쓴다. 최소 크기다.

### 구분선

기본은 **배경 대비**(`crust` < `mantle` < `base` < `surface0`)로 구분하고, 선은 아래에만 쓴다.

| 선을 쓰는 곳 | 이유 |
|---|---|
| 레일 ↔ 본문 ↔ Artifact 패널 | 3분할 구조 |
| Artifact 패널 내부 | 정보 밀도가 높아 배경만으로 부족 |
| 승인 · 충돌 · 로그인 · 에러 카드 | 경고는 눈에 띄어야 함 |
| 입력창 | 입력 가능 어포던스 |
| 모달 외곽 | 떠 있는 레이어 |

대화 영역은 선을 쓰지 않는다. 읽는 영역이라 여백이 낫다.

### 레이아웃

```
┌────────┬──────────────────────┬─────────┐
│  Rail  │  Session Tabs        │ (탭바)  │
│        ├──────────────────────┼─────────┤
│ 프로젝트│  Conversation        │Artifacts│
│ 승인   │                      │ (접기)  │
│ 실행중 ├──────────────────────┤         │
│ 사용량 │  Prompt              │         │
└────────┴──────────────────────┴─────────┘
```

- 그리드 배치는 `col-start` / `row-start` 로 **명시**한다. 탭 바가 조건부로 사라질 때
  자동 배치가 어긋난다.
- 상단 가로 헤더는 두지 않는다. 프로젝트명은 레일에 이미 있다.
- 대화 상단 페이드는 **스크롤됐을 때만** 띄운다. 항상 띄우면 첫 메시지를 가린다.
- **세션 탭바에 가로 스크롤을 두지 않는다.** 탭은 남는 폭을 나눠 쓰다가(최대 220px),
  한 탭이 116px보다 좁아질 상황이면 나머지를 넘침 목록(`⌄ N`)으로 뺀다.
  활성 세션은 넘침 대상이어도 탭으로 끌어올린다 — 지금 보는 것이 안 보이면 안 된다.
  가용 폭은 창 크기·Artifact 패널 폭에 따라 바뀌므로 `ResizeObserver` 로 관찰한다.

## 15. 이 환경에서 밟은 함정

같은 실수를 반복하지 않기 위한 기록. 대부분 프록시 환경·WSL·한글 경로에서 나왔다.

**조용한 폴백을 만들지 않는다.** 문법 강조 실패를 평문으로 넘기던 동안 원인(CSP·WASM)을
알 수 없었다. 실패는 화면에 남겨야 진단이 된다. 아래 두 건은 그렇게 잡혔다.

| 증상 | 원인 | 대응 |
|---|---|---|
| `SELF_SIGNED_CERT_IN_CHAIN` | TLS 검사 프록시가 Electron 헤더 다운로드 차단 | 네이티브 모듈을 쓰지 않는다 → `node:sqlite` |
| `Electron uninstall` | postinstall 이 조용히 실패 | `node node_modules/electron/install.js` 수동 실행 |
| WSL 세션이 인증 실패 | `wsl.exe -- claude` 가 **Windows npm 설치본**을 잡음 (interop PATH) | 탐지된 **절대경로**로 실행 |
| `spawn EINVAL` | Node 보안 수정으로 `.cmd`/`.bat` 직접 spawn 불가 | `cmd.exe /c` 로 감싸고 인자는 배열로 |
| 화면이 반응 없이 멈춤 | spawn 동기 throw → IPC 거부를 렌더러가 미처리 | 예외를 `status:'failed'` 이벤트로 변환 + 렌더러 catch |
| 큰 이미지 첨부 실패 | `String.fromCharCode(...arr)` 인자 개수 초과 | 32KB 청크로 나눠 base64 변환 |
| 드래그앤드롭 무반응 | 입력창에만 핸들러 → 자식이 삼키거나 Electron 기본 동작 | **창 전체**에서 수신 + `will-navigate` 차단 |
| Annotation 텍스트 입력 안 됨 | Electron 은 `window.prompt` 미지원 | 캔버스 위 인라인 입력창 |
| cmd.exe 가 한글 경로를 못 찾음 | bash→cmd 인코딩(UTF-8→CP949) | PowerShell `-EncodedCommand` (UTF-16LE base64) |
| Node 에서 한글 경로 깨짐 | `URL.pathname` 퍼센트 인코딩 | `fileURLToPath` |
| CLI 가 3초 지연 후 경고 | stdin 미지정 | `stdio: ['ignore', ...]` |
| diff 색이 안 보임 | 클래스 + 외부 CSS 가 어딘가에서 묻힘 | 줄 배경을 **인라인 스타일**로 직접 지정 |
| 문법 강조가 조용히 평문으로 폴백 | shiki 기본 oniguruma 엔진이 **WASM** 을 쓰는데 렌더러 CSP(`script-src 'self'`)가 차단 | CSP 를 풀지 않고 `createJavaScriptRegexEngine({forgiving:true})` 로 교체 |
| 코드 블록이 한 줄씩 띄어 보임 | shiki 는 줄 span 사이에 **개행 문자**를 넣는다. `.line{display:block}` 을 주면 블록 줄바꿈 + 개행 = 두 줄 | `code{white-space:normal}` 로 개행을 접고 `.line{white-space:pre}` 로 줄 안 공백만 보존 |
| 후속 지시마다 세션 탭이 늘어남 | `start()` 가 매번 `randomUUID()` 로 새 세션 행을 만듦. CLI 는 `--resume` 해도 새 세션 id 를 준다 | `continueSessionId` 로 기존 행에 이벤트를 이어 쌓는다 (제목·스냅샷 유지) |
| 승인 폴링 타이머 중복 | 같은 세션에 `broker.attach()` 재호출 → 타이머 하나 더 + 세션 허용 초기화 | attach 를 멱등하게 (이미 있으면 dir 만 갱신) |

### 개발 환경 메모

- 파일 편집은 WSL 에서, `npm` / `electron` 실행은 Windows 에서 한다.
- WSL 에서 Windows 명령을 돌릴 때는 PowerShell `-EncodedCommand` 를 쓴다.
  프로젝트 경로에 한글이 있어 `cmd.exe` 직접 호출은 실패한다.
