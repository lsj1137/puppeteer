# 멀티프로젝트 AI 에이전트 워크스페이스 — 기획서

원본 PDF 기획서를 구현 검토 결과에 따라 개정한 작업본. 기술 구현 방식은 `기술스택.md` 참조.

> **읽는 법.** 이 문서는 *무엇을 왜 만들려 했는가* 를 남긴 기획 기준선이다. 구현하면서 더 나은
> 답을 찾아 바꾼 곳이 있고, 그 경우 **현재 동작은 `기술스택.md`(구현)와 `진행상황.md`(현황)가
> 정본**이다. 기획과 갈라진 지점은 아래 표에 모아 두었다 — 기획 문장을 지우지 않은 이유는
> 왜 그렇게 정했다가 왜 바꿨는지가 같이 남아야 다음 판단이 서기 때문이다.

## 기획 ↔ 구현이 갈라진 지점

| 기획 | 현재 구현 | 왜 |
|---|---|---|
| Agent 를 프로젝트 하위에 둔다 | **전역 라이브러리**(`<userData>/agents`)가 정본이고 `x-workspace.projects` 로 적용 대상을 건다 | 같은 Agent 를 여러 프로젝트에서 쓰고, 러너 홈이 WSL/Windows 로 갈리는 문제를 피한다 |
| Agent 마다 권한 정책·Worktree 정책 | 승인 정책은 **세션 단위**(`매번 확인`/`자동 승인`), Worktree 정책은 **프로젝트 단위** | 같은 Agent 라도 상황마다 위험도가 다르다. 정책을 Agent 에 묶으면 매번 정의를 고쳐야 한다 |
| Agent 패키지 파일 내보내기·가져오기, Copy/Linked 2종 | 단일 Markdown 또는 `SKILL.md` 한 장. Linked 만 지원 | 패키지 포맷은 우리만 읽을 수 있다. 한 장짜리 파일이 다른 도구와도 호환된다 |
| 프로젝트마다 Default Agent 제공 | 없음. Agent 없이 실행하거나 `자동 선택` 을 쓴다 | 기본 Agent 는 아무 역할도 아니어서 실익이 없었다 |
| 승인 요청을 전역 Inbox 에 **저장** | 앱 재시작·세션 종료 시 미결 승인을 **폐기** | 죽은 프로세스의 승인은 응답할 곳이 없다. 남겨두면 누를 수 있는 것처럼 보인다 |
| 승인 만료는 실패가 아니라 보류 후 재개 | 훅 대기 한도(285초)를 넘기면 **거부로 확정**하고 알린다 | 훅이 이미 빠져나가 응답 파일을 소비하지 않는다. 되살릴 경로가 없다 |
| 프로젝트 내부 쓰기는 자동 허용 | 내부·외부 모두 승인을 묻고, 경로 안팎은 **위험도 표시**만 가른다 | 프로젝트 안이라고 안전한 게 아니다. 읽기만 훅을 안 태운다 |
| 세션 생성 시 실행 위치 선택 | 프로젝트 Worktree 정책(`사용 안 함`/`자동 병합`/`병합 제안`)에 따라 자동 | 세션마다 고르게 하면 동시에 굴릴수록 실수가 는다 |
| Memory 3계층 | 4개 — Global · Project · **자동** · Agent | CLI 가 스스로 쌓는 자동 메모리를 따로 보여줘야 했다 |
| Project Memory 정본은 `CLAUDE.md` | **`AGENTS.md`** 가 정본, `CLAUDE.md` 는 `@AGENTS.md` 한 줄 다리 | 도구 중립 이름 하나로 여러 CLI 가 같은 파일을 읽는다 |
| Overview 에서 지시 입력 → Agent 제안 | 라우팅 입력은 Agents 화면, 그리고 세션 입력창의 `자동 선택` | 홈에는 승인·대화 흐름이 없어 실행을 이어가기 어려웠다 |
| 프로젝트 메뉴 Tasks/Sessions/Git/Attachments | 화면은 프로젝트·Overview·Agents·Memory·Skills. Git·파일은 우측 패널 탭 | 세션이 상단 탭으로 올라가면서 별도 화면이 필요 없어졌다 |
| 터미널 뷰 | **불가능으로 결론.** node-pty 네이티브 빌드가 이 환경에서 막힌다 | `기술스택.md` §15 |
| 멀티 Agent 는 worktree 정리 회귀 완료 후 착수 | 순서가 뒤집혔다. 멀티 Agent 를 먼저 구현해 `v0.1.0` 으로 게시했고 worktree 정리 항목은 남았다 | `진행상황.md` 안정화 게이트 절에 미충족 상태로 명시 |

## 1. 제품 정의

여러 프로젝트에서 실행되는 Claude Code, Codex 등의 AI 코딩 세션과 프로젝트 전용 에이전트를 하나의 GUI에서 관리하는 **로컬 데스크톱 애플리케이션**.

사용자는 프로젝트별 작업 화면에서 세션을 실행하고, 전체 세션 상태와 승인 요청을 중앙에서 관리한다.

핵심 기능:

- 여러 프로젝트 및 세션 중앙 관리
- 일반 세션과 Project Agent 세션 지원
- 중앙 승인 처리
- 대화와 Artifact 분리
- 이미지 첨부 및 Annotation
- Global · Project · Agent Memory
- Global · Project · Agent Skills
- Project Agent 권한과 작업 범위 설정
- Agent 내보내기 · 가져오기 및 원격 연결
- Worktree 기반 병렬 작업
- Snapshot, Resume, Checkpoint
- 토큰 사용량 및 비용 표시

## 3. 프로젝트 관리

- 로컬 디렉토리를 프로젝트로 추가
- 폴더 드래그 앤 드롭으로 프로젝트 추가
- Git 저장소, 메모리 파일, Skills 및 프로젝트 설정 자동 탐지
- 프로젝트 제거 시 실제 디렉토리는 삭제하지 않고 Workspace 등록만 해제 (제거 전 확인 모달)
- 프로젝트별 화면과 UI 상태 유지

각 프로젝트는 앱 내부에서 하나의 전체 화면으로 구성한다.

```
Ctrl + ←    이전 프로젝트
Ctrl + →    다음 프로젝트
Ctrl + Space  Command Palette
```

전체 Overview에서는 모든 프로젝트와 세션 상태를 확인한다.

Overview에서 지시를 바로 입력할 수도 있다. 프로젝트를 먼저 고르지 않고 "무엇을 해야 하는지"만
적으면, 등록된 모든 프로젝트의 Project Agent 중 알맞은 하나를 찾아 제안한다.

- 제안은 에이전트 이름·프로젝트·선택 이유를 보여주고, 사용자가 실행을 눌러야 세션이 시작된다
- 제안이 마음에 들지 않으면 후보 목록에서 직접 고른다
- 어느 에이전트도 맞지 않으면 그렇게 알려준다 (억지로 고르지 않는다)

## 6. 세션 관리

### 일반 세션

Project Agent를 선택하지 않고 Claude Code 또는 Codex 세션을 바로 시작한다. 적용되는 항목:

- Global Memory
- Project Memory
- Global Skills
- Project Skills
- 현재 Task Context
- 첨부파일

### Project Agent 세션

선택한 Project Agent의 설정을 추가로 적용한다.

- 역할 지침
- Agent Memory
- 선택된 Skills
- 파일 접근 범위
- 권한 정책
- Worktree 정책
- 권장 CLI

### Resume

동일한 작업을 계속할 때는 기존 Provider 세션을 Resume한다. 앱은 내부 Session ID와 Claude Code · Codex의 실제 Session ID를 함께 저장한다.

## 7. 세션 상태 관리

프로젝트 화면 하단에 현재 프로젝트의 활성 세션을 표시한다.

| 상태 | 의미 |
|---|---|
| Starting | 시작 중 |
| Running | 실행 중 |
| Waiting for Input | 사용자 입력 대기 |
| Approval Required | 승인 대기 |
| Auth Required | CLI 로그인 필요 |
| Completed | 완료 |
| Failed | 실패 |
| Stopped | 중지됨 |
| Disconnected | 연결 끊김 |

세션 항목에 표시하는 정보:

- 일반 세션 또는 Project Agent 이름
- 실행 CLI
- 작업명
- 현재 상태
- 실행 시간
- 최근 활동
- 변경 파일 수
- 토큰 사용량

세션을 클릭하면 해당 대화로 이동한다. (터미널 뷰는 node-pty 빌드 불가로 만들지 못했다.)

## 8. 중앙 승인 처리

어느 프로젝트 화면을 보고 있더라도 다른 세션의 승인 요청을 처리할 수 있다.

승인 알림 표시 항목: 프로젝트 / 세션 / 요청 종류 / 명령 또는 작업 내용 / 작업 디렉토리 / 위험도.

### 지원 동작

| 동작 | 의미 |
|---|---|
| Allow Once | 이번 호출만 허용 |
| Allow for Session | 해당 세션 동안 같은 종류 자동 허용 |
| Deny | 사유와 함께 거부 |
| Open Session | 세션 화면으로 이동 (승인은 보류 유지) |

모든 승인 요청은 전역 Approval Inbox에도 저장한다. 고위험 작업은 세션에서 상세 내용을 확인한 뒤 승인하도록 제한할 수 있다.

### 사전 권한 정책

승인 요청 빈도 자체를 줄이기 위한 기본 정책. 프로젝트·Agent 단위로 재정의 가능.

| 작업 | 기본 정책 |
|---|---|
| 읽기 (Read / Glob / Grep) | 자동 허용 |
| 쓰기 (Write / Edit) | 프로젝트 내부 경로면 자동 허용, 외부면 질문 |
| 실행 (Bash) | 항상 질문 |

### 승인 보류

승인 응답이 지연되어 CLI 측 대기 한계를 넘긴 경우, 세션을 실패 처리하지 않는다.

1. 해당 요청을 `보류` 상태로 전환하고 Approval Inbox에 유지
2. 세션에는 "작업이 보류되었으니 종료하지 말고 대기하라"는 취지로 전달
3. 사용자가 나중에 승인하면 세션에 후속 지시를 전달해 재개
4. 세션이 이미 종료된 경우 Resume 후 재지시

**만료는 실패가 아니라 보류 후 재개다.**

## 9. 대화와 Artifact 분리

대화에는 설명, 판단, 질문과 결과 요약만 표시한다. 다음 내용은 별도 Artifact 패널에서 관리한다.

- 코드
- Markdown
- Diff
- 로그
- 실행 결과
- 이미지
- 생성 또는 수정된 파일

대화에는 Artifact 참조 카드만 표시한다.

### 분리 신뢰도

| 출처 | 분리 |
|---|---|
| 도구 호출 결과, 파일 변경, 실행 결과 | 확정 |
| 대화 본문에 포함된 코드 블록 | 사후 파싱으로 분리 |

모델이 대화 본문에 코드를 출력하는 것 자체는 막을 수 없으므로, 앱이 코드 블록을 감지해 Artifact로 이동시킨다. 짧은 코드 블록(기본 5줄 이하)과 인라인 코드는 대화에 남긴다. 임계값은 설정 가능.

### Artifact 기능

- 코드 문법 강조 및 줄 번호
- Markdown 렌더링과 원문 보기
- Git Diff 보기
- 이미지 미리보기
- 파일 경로 복사
- 외부 편집기에서 열기
- 코드 특정 줄을 세션에 참조
- Artifact를 다른 세션이나 Project Agent에 전달

## 11. Memory

적용 순서:

```
Global Memory
→ Project Memory
→ Agent Memory
→ Task Context
→ Session Context
```

| 계층 | 범위 | 변경 |
|---|---|---|
| Global Memory | 모든 프로젝트와 세션 | AI가 자동 수정 불가, 사용자만 직접 변경 |
| Project Memory | 특정 프로젝트 | AI가 제안 가능, 사용자 승인 후 반영 |
| Agent Memory | 특정 Project Agent | AI가 제안 가능, 사용자 승인 후 반영 |

### 저장 원칙

Memory는 **CLI가 실제로 읽는 파일을 정본으로 사용한다.** 앱이 별도 저장소를 두고 세션 시작 시 주입하는 방식은 사용하지 않는다. 앱 밖에서 CLI를 직접 실행해도 동일하게 적용되어야 하기 때문.

### 변경 이력

각 Memory 변경에 대해 다음을 기록한다. 이력은 파일이 아니라 앱이 별도로 관리한다.

- 적용 범위
- 작성자 (사용자 / AI)
- 제안한 세션
- 출처
- 승인 여부
- 생성 및 수정 시각
- 수정 이력

## 12. Skills

Skills는 다음 범위로 관리한다.

```
Global Skills
Project Skills
Agent Skills
```

Project Agent에서는 Skills를 다음 상태로 설정한다.

| 상태 | 의미 |
|---|---|
| Required | 항상 적용 |
| Available | 필요할 때 사용 가능 |
| Disabled | 사용하지 않음 |

동일한 이름의 Skill이 있으면 더 구체적인 범위를 우선한다.

```
Agent Skill > Project Skill > Global Skill
```

앱은 공통 Skill 형식을 관리하고, CLI Adapter가 Claude Code와 Codex에서 사용할 수 있도록 연결한다.

## 13. Project Agent

Project Agent는 프로젝트에 특화된 재사용 가능한 작업자 설정이다.

```
Project Agent = 지속되는 역할과 설정
Session       = Project Agent가 실제 작업을 수행한 실행 기록
```

설정 항목:

- 이름과 설명
- 역할 지침
- 권장 CLI
- Agent Memory
- Required 및 Available Skills
- 읽기 · 수정 가능 경로
- 권한 정책
- Worktree 정책
- 완료 조건과 결과 보고 방식

프로젝트 생성 시 범용 Default Agent를 제공하되, 사용자는 Default Agent를 사용하지 않고 일반 세션을 시작할 수도 있다.

기능: 생성 · 수정 · 삭제 / 템플릿으로 생성 / 기존 세션을 기반으로 생성 초안 작성 / 새 세션 시작 / 기존 세션 Resume / 세션과 작업 이력 확인 / Artifact 전달 / 다른 Agent로 Checkpoint 인계.

---

## 14. Agent Library 및 공유

Project Agent를 로컬 Library에 저장하고 여러 프로젝트에서 재사용할 수 있다.

| 추가 방식 | 의미 |
|---|---|
| Linked | Library 원본의 업데이트를 반영 (수동 승인 후) |
| Copy | 현재 프로젝트에 독립 복사 |

Project Agent는 패키지 파일로 내보내고 가져올 수 있으며, Git 저장소 URL을 Agent source로 연결할 수도 있다.

### 내보내기 항목

| 포함 | 제외 |
|---|---|
| 역할 지침, Skills, 권한 기본값, Worktree 정책, 템플릿, 호환 CLI 정보 | Global · Project · Agent Memory, 세션 기록, 개인 경로, 환경변수 및 비밀값 |

### 가져오기 안전 원칙

외부에서 가져온 패키지는 잠재적 위험 요소다. **패키지가 권한을 주장할 수 없게 하고, 권한은 오직 로컬 사용자가 부여한다.**

| 원칙 | 내용 |
|---|---|
| 선언적 콘텐츠만 허용 | 역할 지침, Skills, 권한 *요청*, 권장 CLI. 실행 스크립트는 기본 차단 |
| 가져오기 전 전문 검토 | 지침 · Skills 전문을 diff로 표시 |
| 권한 기본값 | **전부 거부 상태로 시작**, 사용자가 항목별로 활성화 |
| Bash 권한 | 패키지 요청과 무관하게 항상 질문으로 고정 |
| 스크립트 포함 시 | 별도 명시적 동의 + 코드 전문 표시 + 경고 |
| 설치 직후 | 비활성 상태, 첫 세션 실행 전 재확인 |

### 원격 Agent

Git 저장소 URL을 Agent source로 연결할 때 저장하는 정보: 저장소 URL / 태그 또는 Commit / 설치 버전 / 체크섬 / 업데이트 여부.

특정 버전에 고정하며 자동 업데이트하지 않는다. 업데이트 전 변경된 Instructions, Skills, 권한 및 스크립트를 표시하고 사용자가 직접 승인한다. 원격 Agent의 스크립트와 권한은 신뢰하기 전까지 비활성화한다.

## 15. 동시 수정 감지

같은 프로젝트 디렉토리를 사용하는 여러 세션의 수정 파일을 추적한다.

| 상황 | 처리 |
|---|---|
| 두 세션이 동일 파일을 수정한 것이 확인됨 | **충돌 경고** |
| 세션 기록 없이 파일만 변경됨 | "세션 외부 변경" 표시, 경고 없음 |

오탐이 잦으면 사용자가 경고를 무시하게 되므로, 세션의 실제 파일 수정 기록이 겹칠 때만 경고한다.

### 지원 동작

- 충돌 세션 열기
- 한쪽 세션 중지
- Worktree로 새 세션 시작
- 경고 확인 후 계속

---

## 16. Worktree

같은 프로젝트에서 여러 수정 작업을 동시에 실행할 때 선택적으로 사용한다.

세션 생성 시 선택:

```
Current Project Directory
New Git Worktree
```

앱이 관리하는 정보: Worktree 경로 / 작업 브랜치 / 연결된 세션 / Git 상태 / 병합 여부 / 제거 가능 여부.

**세션 종료만으로 Worktree를 자동 삭제하지 않는다.**

---

## 17. Snapshot과 Checkpoint

### Git Snapshot

세션 시작 전 다음 상태를 기록한다.

- 브랜치
- 기준 Commit
- 수정 파일
- Untracked 파일
- Working Tree 상태

세션 작업 전후의 변경사항을 비교하며, 필요하면 Patch 또는 임시 Commit으로 백업한다.

### Checkpoint

기존 세션을 그대로 이어갈 때는 Resume을 사용한다. Checkpoint는 다음 상황에서 사용한다.

- 새 세션으로 작업 이전
- 다른 CLI로 작업 이전
- 다른 Project Agent로 작업 인계
- 긴 세션을 새 Context로 전환
- 세션 복구용 백업

기록 항목: 완료 작업 / 주요 결정 / 변경 파일 / 관련 Artifact / 첨부 이미지 / 테스트 결과 / 남은 문제 / 다음 작업.

전체 대화 기록은 기본적으로 전달하지 않는다.

## 18. 토큰 사용량 및 비용

세션을 동시에 여러 개 실행하는 특성상 사용량 가시화가 필요하다.

| 범위 | 표시 |
|---|---|
| 세션 | 입력 / 출력 / 캐시 읽기 토큰, 누적 비용 |
| 프로젝트 | 소속 세션 합계 |
| 전역 | 일간 / 월간 합계 |
| Rate Limit | 현재 상태와 리셋 시각 |

세션 상태 바와 Overview에 노출한다.

실측 기준 사소한 프롬프트 1회에도 약 $0.12가 발생한다(글로벌 메모리·스킬이 매 세션 캐시 생성). 세션을 여러 개 띄우는 제품 특성상 사용량 가시화는 선택이 아니라 필수다.

---

## 18-1. 실행 환경 탐지

사용자마다 CLI 설치 위치와 방식이 다르고(Windows / WSL, npm / bun / native), 특정 조합에서 실행이 불안정한 사례가 있다. 앱은 특정 환경을 강제하지 않는다.

- 최초 실행 시 사용 가능한 CLI를 스캔해 목록으로 제시
- 프로젝트별 기본 실행 환경 지정, 세션 생성 시 변경 가능
- 탐지에 실패하면 사용자가 실행 명령을 직접 지정할 수 있다

---

## 19. 인증

CLI 로그인은 각 CLI가 자체적으로 처리한다. 다만 비대화형 모드에서는 로그인 프롬프트가 표시되지 않고 실패하므로, 앱이 이를 감지해 세션 상태를 `Auth Required`로 전환하고 로그인 수단을 제공한다.

## 20. 알림 정책

| 즉시 표시 | 알림 센터에 저장 |
|---|---|
| Approval Required | Completed |
| Waiting for Input | Test Passed |
| Auth Required | Artifact Created |
| Failed | Snapshot Created |
| Disconnected | Memory Update Proposed |
| 동시 수정 충돌 | |

**사용자가 직접 선택하지 않는 한 현재 프로젝트 화면을 자동으로 전환하지 않는다.**
