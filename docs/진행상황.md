한 줄로: **멀티 Agent를 `0.1.0`으로 내보낸 뒤 안정화 게이트를 전부 닫았고, 실사용에서 나오는 잔버그를 patch로 끊어 내보내는 단계다.** 여러 프로젝트·여러

### v0.1.1 (게시 완료)

- 폴더가 사라진 worktree 때문에 세션을 영영 삭제하지 못하던 문제를 고쳤다. 삭제 경로가 연결 상태를
  먼저 보고, 원본을 확인할 수 없으면 폴더를 건드리지 않고 연결만 끊는다.
- worktree 정리 실패는 Git 영어 원문 대신 다음 행동(먼저 커밋·원본에 반영)을 안내한다.
- Git 등록과 앱 DB를 대조해 앱이 모르는 worktree 등록을 걷어낸다. 구 userData 경로에 만든
  worktree가 화면에 보이지 않은 채 남던 문제다.
- 위임이 도는 동안 세션을 실행 중으로 유지해, 새 지시가 보조 결과와 엉키지 않고 예약된다.
- 보조 Agent에서 `Bash`·`PowerShell`을 막았다. 승인 훅에 걸려 10분 동안 아무 결과도 못 내던
  실제 실패를 잡았다.
- Agent의 `readPaths`·`writePaths`는 강제되지 않는다. 조용히 무시하는 대신 세션 시작 때 경고한다.
- 기간 표기(`1월~2월, 3월~4월`)가 취소선이 되던 문제를 고쳤다(`singleTilde: false`).
- Memory 제안 내용이 길면 대화와 검토함 양쪽에서 높이를 제한하고 스크롤한다.
- 문서 4종을 코드와 대조해 정정했다. DB 스키마·라우터 provider 분기·단축키·멀티 Agent 구현 상태와
  기획↔구현이 갈라진 지점을 표로 남겼다.

### v0.3.3 준비 중 — Claude 모델 목록을 CLI 캐시에서 읽는다

Opus 5.5 가 나왔는데 앱에서 고를 수 없다는 문의로 시작했다. **원인은 앱이 아니라 CLI
버전이었다.** Opus 5.5 는 Claude CLI `2.1.280+` 가 필요한데 WSL 은 `2.1.278`, Windows 는
로그인이 풀린 채였다. 앱은 `opus` 별칭을 넘기고, 별칭은 그 CLI 가 아는 최신 Opus 까지만
따라간다.

| 확인한 것 | 결과 |
|---|---|
| 모델 후보 출처 | Claude CLI 는 서버가 준 추가 모델을 `~/.claude.json` 의 `additionalModelOptionsCache` 에 캐시한다 |
| 못 쓰는 모델 표시 | `disabled: true` + 자리표시자 value(`cc-update-required-1`) + «Update to 2.1.280+ to use Opus 5.5» |
| 캐시 갱신 조건 | **실제 세션이 떠야** 갱신된다. `claude mcp list` 같은 부속 명령으로는 안 바뀌고, 로그인이 풀려 있으면 아예 안 바뀐다 |
| 업데이트 후 | Opus 5.5 는 추가 목록에서 빠지고 CLI 내장이 됐다. `opus` 별칭이 `claude-opus-5-5` 로 붙는다 |
| 대화 유지 | 턴마다 CLI 를 새로 띄워 `--resume` 하므로 **CLI 를 올려도 진행 중인 대화가 그대로 이어진다** |

- Claude 도 Codex 처럼 CLI 캐시에서 후보를 읽는다. 별칭(`opus`/`sonnet`/`haiku`) 뒤에
  캐시의 추가 모델을 붙이고, 못 쓰는 항목은 맨 뒤에 회색으로 두고 이유를 그대로 보여준다.
  숨기면 «왜 새 모델이 없지» 에 답할 곳이 사라진다.
- 캐시를 못 읽어도 Claude 는 별칭만으로 쓸 수 있다. 파일이 없는 건 CLI 를 안 돌린 정상
  상태라 경고하지 않고, 깨진 JSON·권한 오류만 알린다. Codex 는 대신할 별칭이 없어 지금처럼
  직접 입력으로 돌린다.
- 모델 슬러그를 앱에 박지 않았다. 새 모델이 나올 때마다 앱을 고쳐야 하기 때문이다. 대가로
  «버전 고정» 은 목록에서 못 고르고 슬러그 직접 입력으로만 된다.
- CLI 탐지는 앱 시작 때 1회라, 업데이트한 버전이 앱을 다시 켜기 전엔 안 보였다. 실행환경
  패널에 **«다시 탐지»** 를 뒀다.

- 못 쓰는 모델이 보이면 모델 패널에 **«CLI 업데이트»** 가 뜬다. 누르면 실행할 명령을
  먼저 보여주고, «실행» 을 눌러야 돈다. 끝나면 다시 탐지하고 모델 목록을 다시 읽는다.

  | 설치 방식 | 명령 |
  |---|---|
  | bun | 실행 파일 **옆의** `bun add -g <패키지>@latest` |
  | Claude npm·네이티브 | `claude update` (CLI 자체 업데이트) |
  | Codex npm | WSL·posix 는 실행 파일 옆 `npm`, Windows 는 `npm.cmd` |
  | 앱 번들 Codex·알 수 없음 | 올리지 않고 이유만 표시 |

  **바 `npm`·`bun` 을 부르지 않는 이유**: WSL 은 interop 으로 Windows PATH 를 뒤에 붙인다.
  이 PC 도 WSL 안에 리눅스 npm 이 없어 `npm` 이 Windows 것으로 잡힌다. 그러면 WSL 설치본이
  아니라 Windows 설치본이 올라간다. WSL 은 세션 실행과 같은 `buildRunnerCommand`(`-e`, 셸
  평가 없음)로 띄운다.
- 업데이트 직후에도 회색 항목이 남을 수 있다. 캐시는 **실제 세션** 에서만 갱신되기 때문이다.
  별칭은 바로 새 모델로 붙으므로 화면에서 그렇게 안내한다.
- Windows 는 실행 중인 CLI 파일을 바꾸지 못한다. 확인 단계에서 «세션이 끝난 뒤에» 를
  안내하고, 실패하면 설치 도구 출력 끝부분을 그대로 보여준다.

### v0.3.2 (게시 완료) — 탭이 넘칠 때 깨지던 세션 머리줄

탭을 여러 개 열면 세 가지가 한꺼번에 어긋났다. **원인은 하나** — 탭 목록이 넘쳐도 잘리지
않고 옆을 밀어냈다.

| 증상 | 실제 원인 |
|---|---|
| 체크포인트·Worktree 버튼이 사라짐 | 탭이 넘쳐 오른쪽 묶음을 창 밖으로 밀어냄 |
| 넘침 버튼(`⌄ N`)이 우측 끝으로 감 | 같은 이유로 밀림 |
| 넘침 목록이 잘려 보임 | 오른쪽 끝에서 `left-0` 으로 펼쳐 창 밖으로 나감 |

- **`shrink-0` 는 «줄이지 않는다» 일 뿐 «밀리지 않는다» 가 아니다.** 오른쪽 묶음에 걸어
  둬도, 탭이 자기 최소 폭 밑으로 못 줄면 그대로 넘쳐 밀어낸다. 탭 목록에 `overflow-hidden`
  을 걸어 **넘치면 잘리게** 했다. 계산이 틀려도 실패 방향이 «탭이 조금 잘림» 이지
  «버튼이 사라짐» 이 아니다.
- **넘침 버튼을 탭 목록 밖으로 뺐다.** 안에 두면 이제 탭과 함께 잘려 «다른 세션» 으로 갈
  길이 없어지고, 목록도 잘리는 영역에 갇힌다. 덤으로 `tabBarRef` 가 재는 폭에서 이 버튼이
  빠져 남은 자리 계산이 실제 탭 공간과 일치하게 됐다.
- 목록은 `right-0` 으로 **왼쪽으로 펼치고** 폭·높이를 창 크기에 묶었다
  (`min(18rem,100vw-2rem)`, `min(20rem,60vh)`). 좁은 창과 세로 배치에서도 안 잘린다.
- 숨긴 세션 목록과 모델 선택 팝오버의 가로 구분선을 없앴다. `v0.1.2` 에서 12군데를 정리할
  때 빠진 것들이다(§13 «가로 구분선을 두지 않는다»).

> 이 판에서 JSX 문법을 한 번 깨뜨렸다(`{cond && ( {/* 주석 */} <div> …` — `&&` 뒤 괄호
> 안은 표현식 **하나**여야 한다). 타입 검사가 잡았지만 **테스트 245개는 그 상태로 전부
> 통과했다.** 이 컴포넌트를 렌더하는 테스트가 없다. 화면 변경은 타입 검사·빌드·실행까지
> 봐야 한다.

### v0.3.1 (게시 완료) — WSL 인자가 셸에서 평가되던 문제

실사용 버그 리포트로 들어왔다. WSL provider 로 **Agent 를 골라** 세션을 시작하면
`/bin/bash: line 1: <토큰>: command not found` 가 수십 줄 쏟아졌다.

**원인은 `--` 였다.**

```
wsl.exe -d Ubuntu --cd <경로> -- /path/claude ... --agents '{"...":{"prompt":"... `코드` ..."}}'
                               └─ 여기부터 전부 로그인 셸이 읽는다
```

대부분의 POSIX 도구에서 `--` 는 «뒤는 옵션이 아니라 값» 이라 안전해 보인다. **wsl.exe 는
다르다.** `--` 는 wsl 자신의 옵션 파싱만 끝내고, 명령은 그대로 기본 로그인 셸에 실린다.
셸을 건너뛰려면 `-e` 를 써야 한다.

- 셸을 통과한 것은 `--agents` 로 넘기는 **Agent 지침 전문**이다. 마크다운이라 인라인 코드
  백틱이 사방에 있고, 그게 명령 치환으로 **실행**됐다. 마크다운 문서 하나로 임의 명령
  실행이 되므로 릴리스 블로커로 다뤘다.
- 시스템 프롬프트·스킬·프로젝트 지침은 원래부터 stdin 이라 무사했다(`buildClaudePrompt`).
  Agent 를 안 쓰면 argv 에 사용자 텍스트가 없어 그동안 드러나지 않았다.
- 더 나쁜 건 **조용한 손상**이었다. 치환 결과(대개 빈 문자열)가 들어가 지침 일부가 소리
  없이 사라진다. 오류가 안 보여도 이미 망가져 있었을 수 있다.

수정은 `-e bash -lc 'exec "$0" "$@"'`. `-e` 로 셸을 끊되 로그인 환경(nvm·PATH·인증)은
`bash -lc` 한 겹으로 유지한다. **스크립트가 고정 문자열**이고 실행 파일·인자는 `$0`·`$@`
로 받으므로 다시 해석되지 않는다. 이스케이프로 때우는 방식은 인용 규칙이 provider·OS 별로
갈려 재발하므로 쓰지 않았다. Claude·Codex 가 같은 함수를 쓰므로 함께 고쳐졌다.

> 진단이 헷갈렸던 이유: **백틱은 명령행 전체에서 짝을 맺는다.** 한 인자의 백틱이 열리면
> 뒤 인자까지 삼켜서, 관계없는 자리의 토큰이 오류 메시지에 딸려 나온다. 오류에 찍힌 위치가
> 원인 위치가 아니다.
>
> 복창 테스트(«이 토큰을 그대로 출력하라»)는 **판정 근거가 못 된다.** 셸이 치환한 경우와
> 모델이 알아서 확장한 경우의 출력이 같다. 확실한 증거는 ① 원래의 `command not found` 가
> 사라졌는지 ② 받은 시스템 프롬프트에 원문이 그대로 있는지다.

### v0.3.0 (게시 완료) — 기간 조회와 업무보고

«지난 주에 뭘 했는지» 를 모아 업무보고로 쓰려는 요구에서 나왔다.

**Overview 정리**

- 스크롤이 없어 아래가 잘렸다. `h-full min-h-0` 이 빠져 내용 높이만큼 늘어나 바깥에서
  잘리고 있었다 — 다른 전체 화면(Memory·Skills·Agents)은 전부 갖고 있던 것이다.
- 프로젝트 카드에서 경로 줄을 툴팁으로 옮겨 세 줄을 두 줄로 줄였다. 잘려서 안 읽히는
  경로가 카드 높이의 3분의 1을 먹고 있었다. 열 수도 고정 2열에서 폭에 맞춰 늘어나게 바꿨다.

**기간 필터**

- 오늘·이번 주·지난 주·이번 달·지난 달·전체·직접 지정 + 프로젝트. 기본은 «이번 주».
- 계산은 `lib/period.ts` 의 순수 함수다. 세 가지를 테스트로 못 박았다.
  - **주는 월요일 시작** — 일요일 시작이면 주말 작업이 다음 주로 넘어간다
  - **구간은 반열림**(`from ≤ 시작 < to`) — 닫힌 구간이면 자정에 시작한 세션이 이틀에 걸린다
  - **기준은 시작 시각** — 자정을 넘겨 끝난 세션도 시작한 날 것이다
- 기준 시각은 상태로 붙잡는다. 렌더마다 `Date.now()` 를 부르면 구간이 매번 새 값이 되어
  조회가 끝없이 다시 돈다. 같은 프리셋을 다시 누르는 것이 «지금 기준으로 새로고침» 이다.
- **숨긴 세션도 넣는다.** 숨김은 «탭에서 치웠다» 는 뜻이지 «안 한 일» 이 아니다. 빼면
  보고에서 일이 조용히 누락된다. 대신 보고서 사실에 «숨김» 으로 표시한다.

**기간 보고서**

- 필터 줄 오른쪽 끝 버튼 → 지금 보고 있는 기간·프로젝트가 그대로 대상이다.
- **세션을 만들지 않는다.** 라우팅이 쓰던 일회성 호출을 `cli-once.ts` 로 빼서 공용화했다.
  세션으로 돌리면 목록이 오염되고 **그 세션이 다음 기간 조회에 다시 잡힌다** — «이번 주 한 일»
  에 «보고서를 만들었다» 가 들어간다.
- **도구를 막는다.** 사실을 전부 프롬프트에 실으므로 파일을 읽을 이유가 없다. 보고서를
  만들다 승인 카드가 뜨면 흐름이 끊긴다.
- **원본 사실을 나란히 둔다.** 모델이 쓴 문장만 남으면 맞는지 확인할 방법이 없다. CLI 가
  실패해도 이 탭은 남아 복사해 직접 정리할 수 있다.
- 세션마다 지시(5개·200자)·마지막 응답(500자)·바뀐 파일(10개)·산출물·비용을 뽑는다.
  실패로 끝난 응답은 «무엇을 했다» 가 아니므로 제외한다.
- 총량 6만 자를 넘으면 **오래된 것부터** 제목만 남기고, **무엇이 줄었는지 밝힌다.**
- 요청 문구는 고칠 때마다 자동 저장된다. 보고 양식은 사람마다 달라 한 번 다듬으면 계속 쓴다.
- 저장은 경로·이름을 사용자가 고른다. 기본 이름은 `2026-08-24_업무보고.md` — 날짜가 앞이라
  파일 목록이 시간순으로 정렬된다.

**프롬프트는 항상 stdin 으로**

보고서를 붙이자 «`/bin/bash: command substitution`» 으로 실패했다. 일회성 호출만 프롬프트를
**명령행 인자**로 넘기고 있었고, WSL 은 명령을 셸에 태우므로 사실 번들 안의 백틱(파일 경로를
감싼다)이 명령 치환으로 해석됐다. 라우팅 프롬프트에는 백틱이 없어 그동안 드러나지 않았다.

세션 실행 경로는 이미 stdin 을 쓰고 있었다(`claude-cli.ts:64`). 일회성 호출도 맞췄다.
이 수정으로 **아직 안 터진 두 번째 문제**도 막혔다 — 사실 번들 상한 6만 자는 Windows 명령행
한도(약 3만 2천 자)를 넘어, WSL 이 아니어도 `ENAMETOOLONG` 으로 실패했을 것이다.

### v0.2.0 (게시 완료) — 세로 배치와 접히는 레일

창을 좁게 쓰거나 세로로 세워 쓸 수 있게 만든 판이다. 화면을 나눠 두 가지를 같이 보려는
요구에서 출발했다.

**창 비율로 배치를 정한다**

- 세로 진입은 `높이/너비 ≥ 1.05`, 가로 복귀는 `≤ 0.95`. 두 임계값 사이에서는 직전 배치를
  유지한다. 임계값이 하나면 정사각에 가까운 창을 끄는 동안 매 프레임 레이아웃이 뒤집힌다.
- 판정은 `lib/layout-mode.ts` 의 순수 함수로 빼고 훅은 `resize` 구독만 한다. 히스테리시스
  구간·크기 0·설정 고정까지 테스트로 못 박았다.
- 설정 «화면 배치»에서 자동·가로 고정·세로 고정을 고른다. 고정이 창 비율보다 우선한다.
- 창 최소 폭을 `1100 → 760` 으로 내렸다. 1100 이면 높이가 1100 을 넘는 화면에서만 세로가
  되는데 그런 화면은 드물다. 만들어도 안 보이는 기능이 됐을 것이다.

**세로에서 달라지는 것**

- 가로는 3열(레일·대화·Artifacts) × 3행, 세로는 2열(레일·본문) × 4행. Artifacts 가
  우측 열에서 **탭 바 바로 아래 행**으로 올라간다.
- Artifacts 를 대화와 입력창 **사이**에 두면 «읽고 바로 답한다» 는 흐름이 끊긴다. 대화
  아래 → 맨 아래 → 맨 위로 옮겨 가며 맞췄다. 참고용 패널이 주 흐름을 가르지 않는 자리가 맞다.
- 그리드 좌표는 컴포넌트에 하드코딩하지 않고 `GRID_AREAS` 에서 `area` prop 으로 내려준다.
  한 군데만 빠뜨리면 겹쳐 그려진다.
- 레일 접기 상태와 Artifacts 크기는 배치별로 따로 저장한다(`ws.rail`/`ws.rail.portrait`,
  `ws.artifactW`/`ws.artifactH`). 세로는 접힘이 기본 — 가로에서 펼쳐 둔 레일이 그대로
  넘어오면 좁은 창의 3분의 1을 먹는다.

**레일 접기**

- `Ctrl+B`·머리 버튼·명령 팔레트 세 경로. 접으면 52px 아이콘 열이 된다.
- 접혀도 일이 되게 남겼다. 프로젝트는 **첫 글자 버튼**으로 전환하고 실행 중이면 초록 점,
  승인 대기는 방패 + 건수로 뜬다. 접었다고 아무것도 못 하면 접는 의미가 없다.
- 아이콘만 남으면 묶음 경계가 사라져 한 줄로 읽힌다. 머리·화면 전환·프로젝트·사용량 사이에
  구분선을 넣었다.

**창 크기에 맞춰 줄어드는 패널**

- Artifacts 폭이 고정값이라 창을 좁히면 패널은 그대로인 채 대화만 짓눌렸다. 이제
  `창 폭 − 레일 − 대화 몫(380)` 까지만 내준다. 높이도 창 높이의 70% 까지다.
- **저장값은 건드리지 않고 그리는 값만 줄인다.** 저장값을 덮어쓰면 창을 한 번 좁힌 것으로
  사용자가 정한 폭이 영영 사라진다.
- 패널이 380px 보다 좁으면 탭 글자를 지우고 아이콘만 남긴다. 넷을 글자까지 붙여 두면 줄이
  넘쳐 접기 버튼이 밀려났다.

**여닫는 전환**

- 레일 폭과 Artifacts 폭·높이를 **그리드 트랙**에 싣고 `grid-template-columns/rows` 에
  200ms 전환을 걸었다. 패널이 크기를 직접 들고 있으면 트랙만 전환되고 패널은 따로 논다.
- 세로 접힘 손잡이는 `40px` 로 못 박고 그리드 행도 같은 값을 쓴다. 행이 `auto` 면 접힘과
  펼침이 서로 다른 요소라 이어서 움직일 값이 없어 툭 끊긴다.
- 크기를 끄는 동안에는 전환을 끈다. 켜 두면 패널이 커서를 한 박자 늦게 쫓아온다.

### v0.1.2 (게시 완료)

실사용에서 나온 «눌렀는데 반응이 없다 / 화면이 제멋대로 움직인다 / 느리다» 를 모아 끊는 판이다.
기능 추가는 없고 응답성·일관성만 손봤다.

**스크롤과 화면 이동**

- 승인 처리 후 복귀할 때 읽던 자리로 정확히 돌아간다. 픽셀 위치만 저장하면 두 가지로 어긋났다.
  복원 시점에 대화가 덜 그려져 있으면 브라우저가 최대 스크롤로 잘라내 바닥으로 튀었고(요청값이
  아니라 실제 도달 위치로 판단하고 도달할 때까지 재시도해 막았다), 복원 뒤 코드 강조 등으로 위쪽
  높이가 늘면 같은 픽셀이 더 앞쪽 내용을 가리켰다. 후자는 픽셀 대신 **화면 맨 위에 걸친 대화
  항목을 기준**으로 삼아 해결했다. 이를 위해 모든 대화 항목에 DOM id를 달았다(전에는 사용자
  메시지에만 있었다).
- 지시를 넣은 직후 다른 프로젝트로 옮기면 세션 탭이 남의 프로젝트 것으로 바뀌었다. 시작 응답이
  돌아왔을 때의 «지금 보고 있는 프로젝트»와 요청 당시 프로젝트를 비교해, 떠났으면 목록을
  건드리지 않는다(`canApplyStartedSession`).
- 예약한 지시가 나갈 때 화면을 그 세션으로 끌고 가지 않는다. 다른 것을 보던 중이라면 4초 뒤
  사라지는 알림만 띄운다. 세션 완료 알림은 놓치면 안 되므로 그대로 남긴다.

**Memory 화면**

- 제안 검토를 편집창 **아래 초록 꼬리**로 바꿨다. 정본은 항상 끝에 추가되므로 그 자리에 이어
  붙이면 저장될 모양의 미리보기가 된다. 카드 껍데기를 걷어내 제안이 쌓여도 편집창이 밀리지 않는다.
- 한 번에 **한 건만** 보여준다. 머리줄에 `N / M`·이동(`‹ ›`)·결정(`✓ ✕`)을 모으고 본문은
  내용 길이와 무관하게 **같은 높이**를 차지한다. 여러 건을 동시에 펼치면 기존 Memory 가 잘려
  나가고, 높이가 매번 달라지면 다음 건으로 넘길 때 화면이 흔들렸다.
- 왼쪽 제안 목록에서 고른 제안이 오른쪽에 그대로 열린다. 전에는 항목만 열고 순번을 늘 0 으로
  둬서, 같은 프로젝트의 두 번째·세 번째 제안을 누르면 **아무 반응이 없었다**.
- 항목을 눌렀는데 안 바뀌던 문제를 고쳤다. 목록 읽기와 사용자 클릭의 내용 읽기가 겹쳐 늦게 온
  응답이 나중 선택을 덮었다. 읽기마다 번호를 매겨 마지막 요청만 반영한다.
- 대상이 목록에 없는 제안을 눌렀을 때 조용히 무반응이던 자리에 이유를 남긴다.

**Memory 목록 성능**

| 고친 것 | 이유 |
|---|---|
| 세션 기록(jsonl)에서 앞 4KB 만 읽는다 | 전체를 읽어 앞 4000자만 쓰고 있었다. 기록은 수십 MB 까지 자란다 |
| 폴더→cwd 대응을 `app_setting` 에 저장 | 디렉터리 이름이 cwd 에서 만들어지므로 대응은 변하지 않는다. 앱을 다시 켜도 기록을 열지 않는다 |
| `existsSync` + `statSync` → `statSync` 하나 | 존재 여부는 stat 으로 함께 알 수 있다. WSL UNC 경로에서 왕복이 두 배였다 |

| 세션 시작 때 Memory 목록을 훑지 않는다 | 제안 대상은 규칙으로 바로 계산된다(`projectMemoryId`). 자동 메모리까지 뒤질 이유가 없었다 |

**디자인 일관성**

- Skills 편집기 머리 영역을 다시 짰다. 라벨 없는 입력 넷이 같은 모양으로 쌓여 있어 채우기 전엔
  어느 칸인지 알 수 없었다. 이름은 제목으로, 나머지는 `설명`·`범위` 라벨을 붙인 두 줄로 묶고,
  범위는 왼쪽 목록과 같은 색의 세그먼트 단추로 바꿨다. 못 고르는 범위는 이유를 알려준다.

### v0.0.9 이후 현재 작업

#### 세션·대화 UI

- 입력창 위에 실행 환경·Agent·자동 반영 상태를 독립 버튼으로 제공하는 세션 도구 모음을 만들었다.

  핸들은 입력 영역을 밀지 않으며 도구 모음 상단 중앙에 붙는 얇은 탭으로 표시한다.
- 대화가 맨 아래에서 벗어나면 우측 아래에 하단 이동 버튼을 표시하고, 하단에 도달하면 숨긴다.
  긴 구분선처럼 공백 없는 문자열도 대화 폭을 밀지 않도록 줄바꿈한다.
- 새 응답이 올라와도 사용자가 하단(48px 이내)을 따라가고 있을 때만 자동으로 스크롤한다. 위쪽을
  읽는 중이면 위치를 유지하고, 세션을 바꿨다 돌아오거나 승인 처리 후 복귀할 때는 떠날 때의
  스크롤 위치를 복원한다.
- 위쪽을 읽는 동안 같은 세션 아래에 승인 요청이 생기면 하단 이동 버튼 위에 `승인 요청 N` 배지를
  띄운다. 배지를 누르면 승인 영역으로 이동하고, 처리 후에는 원래 보던 위치로 돌아온다.
- 프로젝트를 선택하면 세션 목록만 불러오는 데 그치지 않고 가장 최근 생성된 세션을 실제 선택해
  대화까지 복원한다.
- 세션 탭의 연필 버튼이나 더블클릭으로 이름을 인라인 수정할 수 있고, 프로젝트 목록은 드래그로

- 입력 기록 `↑`/`↓` 탐색과 실행 중 다음 지시 한 건 예약을 지원한다. 예약 지시는 새 세션이 아니라
  예약 당시 세션으로 이어 보내며 취소할 수 있다.
- 실행 환경과 Agent 선택은 입력창 바로 위에서 필요한 순간 접근한다. 실행 환경이 왼쪽, Agent가
  오른쪽 순서다.
- 사용량은 기본 접힘 상태에서 아이콘·레이블·진행률·퍼센트만 보여주고 펼치면 상세 내역을 표시한다.

  남은 보류 내역은 사용자가 직접 지울 수 있다.
- 모달은 실수로 바깥 영역을 눌러도 닫히지 않고 `Esc` 또는 명시적인 닫기 버튼으로만 닫는다.
  Agent 편집·가져오기와 Checkpoint처럼 작성 내용을 잃을 수 있는 창은 변경사항이 있으면 닫기 전에
  저장하지 않은 내용을 폐기할지 다시 확인한다.
- Windows 창은 개발 실행과 설치본 모두 `Puppeteer` 앱 이름, 공통 AppUserModelID와 같은 아이콘
  경로를 작업표시줄 상세 정보에 명시하며 충돌 해결 보조 창에도 동일하게 적용한다.
- Windows 셸에는 PNG 대신 16~256px 다중 해상도 `resources/icon.ico`를 전달한다. 개발 실행과
  설치 실행 파일도 같은 ICO를 사용해 Electron 기본 아이콘으로 되돌아가는 경로를 제거했다.
- 프로젝트 목록은 별도 드래그 아이콘이나 방향 화살표 없이 항목 전체를 끌어 순서를 바꾼다.
  드래그 중인 항목과 이동 대상만 배경·윤곽·그림자로 강조한다. 프로젝트 별칭을 저장할 수 있으며
  비어 있으면 폴더명을 표시한다. 항목 아래 보조 줄은 실행 환경을 왼쪽에, Worktree 정책을 오른쪽
  끝에 고정해 항목마다 위치가 흔들리지 않게 한다.
- 개발 실행은 설치본과 다른 `.dev` AppUserModelID를 사용해, Windows가 고정된 설치본 바로가기의
  캐시 아이콘으로 개발 창을 묶지 않도록 한다.
- 다른 프로젝트나 세션에서 승인 항목으로 이동한 경우 기존 위치를 임시 저장하고, 승인 또는 거부가
  처리되면 직전에 보던 프로젝트·세션·전역 화면으로 자동 복귀한다.
- 승인 대상으로 이동한 세션에 요청이 여러 개면 중간마다 복귀하지 않고, 해당 세션의 마지막 요청을
  처리한 뒤에만 기존 위치로 돌아간다.
- 대화 본문의 연결된 아티팩트를 누르면 우측 패널을 자동으로 펼치고 아티팩트 탭과 해당 항목을 선택한다.
- 설정의 기본 실행환경은 새 세션 실행 우선순위의 실제 fallback으로 사용한다. 세션 지정값과 프로젝트
  지정값이 없을 때 저장된 기본값을 사용하며, 사용할 수 없는 환경은 선택하지 않는다.
- 실행 중 세션에 예약한 다음 지시는 대상 세션 ID와 함께 유지하고, 다른 세션에서는 예약 배너와
  예약 상태를 숨긴다. 대상 세션이 끝나면 화면 위치와 무관하게 원래 세션으로 전송한다.
- 첫 세션의 실행환경 선택 목록은 각 항목에 `Claude`·`Codex` provider 배지를 먼저 표시하고,
  Windows·WSL 위치와 버전은 보조 정보로 분리한다.

#### 우측 보조 패널

- 지시·Git·Artifacts·Files를 탭으로 분리하고 패널 전체를 접을 수 있게 했다. 지시 탭은
  사용자의 질문과 지시를 시간순으로 보여주며 선택하면 해당 대화 위치로 이동한다. Git 저장소가 아닌 폴더에는
  Git 탭을 표시하지 않는다.
- Files 탭은 프로젝트 또는 세션 worktree의 파일 목록과 읽기 전용 미리보기를 제공한다. 바이너리와
  1MB 초과 파일은 내용을 억지로 읽지 않고 이유를 표시한다.
- 선택된 탭은 기존 형태를 유지하면서 배경만 옅게 조정해 라이트·다크 테마의 문자 대비를 높였다.
- Git 탭은 worktree 이름뿐 아니라 최근 커밋의 제목·해시·작성자·시각·ref와 현재
  dirty/ahead/behind/fast-forward 상태, 마지막 자동 반영 진단을 함께 표시한다. Worktree 관리 창은
  중복 조회 정보를 덜어내고 커밋·rebase·병합·충돌 해결·정리 작업에 집중한다.

#### Worktree·Memory·Git

- 저장된 worktree가 원본 Git의 common directory와 계속 연결되어 있는지 재개·정리 전에 확인한다.
  연결이 끊긴 기존 폴더는 삭제하지 않고 별도 경로의 새 worktree를 현재 원본 HEAD에서 만들며,
  정리 시에는 DB 연결만 해제해 다음 지시에서 안전하게 재생성한다.
- Project·자동·Agent Memory의 선택 내용을 실행환경별 Global Memory 정본으로 복사하는 검토 UI를
  제공한다. 원본은 유지하고 같은 내용은 중복 추가하지 않으며, 편집 화면은 Ctrl/Cmd+S 저장을 지원한다.
- 설정 도움말에서 입력 기록, 예약 지시, 이미지 첨부, 프로젝트·세션 이동과 승인 단축키를 확인할 수 있다.

- 자동 반영은 프로젝트별 `자동 병합`과 `병합 제안`을 제공한다. 자동 병합에서 변경이 있으면 worktree
  브랜치에 커밋하고, 원본이 안전할 때만 fast-forward한다. 안전 조건 실패 시 원본을 건드리지 않고
  검토 안내와 실행 경로를 남긴다.
- Worktree 정책은 프로젝트마다 `사용 안 함`·`자동 병합`·`병합 제안`으로 저장한다. 기존 프로젝트의
  안전한 기본값은 병합 제안이며, 사용 안 함은 새 worktree 생성과 자동 Git 반영을 모두 중단한다.
  설정 화면의 선택은 앞으로 추가할 프로젝트의 기본값으로만 사용한다.
- 프로젝트 목록의 연필 버튼은 별칭·Worktree 정책·폴더 재연결을 한 오버레이에서 관리한다.
  Worktree 사용 안 함으로 전환할 때는 프로젝트의 모든 세션을 먼저 검사하고, 실행 중 세션·미커밋
  변경·미병합 커밋·확인 불가능한 Git 상태가 하나라도 있으면 전환과 정리를 중단한다. 모두 안전하면
  등록된 Worktree를 정리한 뒤에만 정책을 저장한다.
- 승인된 Project Memory는 원본의 `AGENTS.md`, `CLAUDE.md`만 별도 커밋한다. 이 때문에 worktree가
  뒤처지면 Memory 충돌이 없는 경우에만 rebase 후 fast-forward하고, 기존 Memory 변경이나 충돌은
  자동으로 덮지 않는다.
- Windows와 WSL에서 줄바꿈 차이만으로 저장소 전체를 dirty로 판단하지 않도록 Git 실행 기준을
  통일했다.
- 동일 worktree의 자동·수동 커밋을 직렬화해 `index.lock` 경쟁을 막는다. 실제 Git 프로세스가 만든
  잠금일 수 있으므로 lock 파일을 무조건 삭제하지 않는다.
- 저장소 단위 변경 큐로 Project Memory 커밋, worktree 커밋, 원본 fast-forward를 직렬화한다.
  자동 반영 중에는 같은 세션의 수동 커밋·rebase·병합을 차단하며, merge 직전 Memory 커밋으로
  작업 브랜치가 뒤처진 경우 상태를 다시 판정해 무충돌 rebase와 fast-forward를 한 번 재시도한다.
- `index.lock` 실패는 잠금 파일의 정확한 경로와 실행 중 Git 종료·잔존 잠금 확인 순서를 진단에 남긴다.
- 자동 커밋 제목은 세션명을 복사하지 않고 실제 diff의 파일·작업 유형을 바탕으로 생성한다. 버전
  변경은 `chore: 버전 <version>로 갱신`으로 인식하며 본문에 파일별 변경량을 모은다. 원본에는
  worktree 커밋 이력을 새 커밋으로 복제하지 않고 fast-forward로 보존한다.
- Electron 메인 프로세스는 hot reload로 새 자동 반영 로직이 교체되지 않을 수 있다. Git 로직을
  수정한 뒤 실환경 검증할 때는 앱을 완전히 종료·재시작해야 한다.
- 개발판이 자기 worktree를 실행하는 동안 rebase로 소스가 교체되면 Vite/Electron 재빌드가 겹칠 수
  있다. 초기 HTML을 어두운 배경으로 고정하고, 렌더러 모듈 로드 오류는 제한적으로 자동 재시도하며,
  반복 실패 시 세션을 종료하지 않는 복구 화면을 표시한다.

#### Agent·Memory·Skills

- 공개 예제는 `agents/release-maintainer.md`, `agents/agent-creator.md`, `agents/git-worktree-doctor.md`
  셋이다. `git-worktree-doctor`는 linked worktree의 경로 오류·dirty·ahead/behind·`index.lock`·자동
  반영 실패를 읽기 전용으로 진단하고 복구 절차만 제시한다. `reset --hard`, `clean -fd`, force push와
  브랜치·worktree 삭제는 하지 않는다.
- 공개 예제 `release-maintainer`에 이어 `agents/agent-creator.md`를 추가했다. Agent 생성 도우미는
  요청을 Agent·Skill·Memory로 먼저 구분하고, Puppeteer가 파싱하는 frontmatter와 `x-workspace`
  스키마로 최소 권한 초안을 만든다. 승인 전에는 파일을 쓰거나 덮어쓰지 않는다.
- Puppeteer Agent는 앱 내부에서 Claude에는 인라인 Agent 정의로, Codex에는 역할 프롬프트로 전달된다.
  Skills는 두 provider 모두에 Required/Available 카탈로그로 연결된다.
- Claude Agent와 Codex Skill은 같은 개념이 아니다. Claude Agent는 역할 프로필로 가져올 수 있지만,
  Codex `SKILL.md`는 반복 절차로 Skill 라이브러리에 넣어 Agent와 조합하는 것이 맞다. 통합 가져오기와
  손실 없는 단일 변환은 하지 않는다. 외부 `SKILL.md`는 원본 형식·매핑 결과·사용하지 않는 frontmatter를
  먼저 보여주고, Global/Project/Agent 범위와 본문을 검토한 뒤에만 정본으로 저장한다.
- Claude의 사용자 지시와 Memory·Skills 시스템 지침은 stdin으로 전달한다. Windows→WSL 명령행 길이와
  분리해 `spawn ENAMETOOLONG`을 막고 한글·따옴표를 그대로 보존한다.
- 프로젝트 기본 실행환경이 비어 있으면 최근 세션의 실행환경을 표시용 기본값으로 복구한다.
- Agent 편집기의 허용·금지 도구는 길이 제한 없는 별도 행으로 표시한다. `Read`, `Glob`, `Grep`,
  `Write`, `Edit`, `Bash`는 버튼으로 추가·해제할 수 있고 직접 쉼표 입력도 유지한다.
- Agent 내보내기는 등록 프로젝트의 Claude/Codex 표준 위치뿐 아니라 사용자가 고른 임의 위치도
  지원한다. Agent Markdown은 파일 경로를 직접 고르고, Codex Skill은 선택한 폴더 아래에
  `<agent-name>/SKILL.md` 구조로 저장한다.
- 승인 정책은 Agent 정의가 아니라 세션별로 관리한다. 입력창 위 세션 도구 모음에서 기본 `매번 확인`과
  `자동 승인`을 전환하며, 실행 중에도 즉시 적용되고 세션 재개 뒤에도 유지한다. 자동 승인은 해당
  세션의 모든 도구 요청을 통과시키므로 명확한 위험 안내를 함께 표시한다.
- Skill 화면은 기존 정본의 본문·설명을 편집하고 Global/Project/Agent 범위를 안전하게 이동할 수 있다.
  이동 대상에 같은 이름이 있으면 덮어쓰지 않으며, 삭제·저장·내보내기 실패를 화면에 표시한다.
  내보내기는 provider에 종속되지 않는 정본 `SKILL.md`를 생성하고 Ctrl/Cmd+S 저장을 지원한다.

### Worktree 기능 브랜치

`feat/worktree-merge` 구현은 완료되어 PR #1로 `main`에 병합했다.
macOS에서 다음 흐름을 실제 프로젝트의 두 세션으로 반복 검증했다.

- 새 세션별 worktree 자동 생성과 기존 세션 이어가기
- worktree 변경 커밋과 diff 확인
- 첫 작업의 fast-forward 병합
- 원본이 앞선 두 번째 작업의 재배치와 후속 병합
- 같은 파일의 겹치는 변경에서 좌우 충돌 해결 후 rebase continue
- 병합 완료 상태 갱신, worktree 정리, 정리된 세션의 상태 표시와 재생성
- worktree 승인 알림에서 원본 프로젝트의 같은 세션으로 이동하고 후속 지시 이어가기

당시 자동 검증은 단위 테스트, 타입 검사, 프로덕션 빌드, Electron smoke와
세션·어댑터·SQLite E2E까지 통과했다.

  Memory 화면은 최신 대기 제안을 자동으로 열어 작은 창에서도 승인 버튼이 잘리지 않게 스크롤한다.
  여러 제안은 전체 정본 diff 대신 각각 실제로 추가될 내용만 보여줘 결정 대상을 분명히 한다.
- Skills를 Global · Project · Agent 3계층으로 관리한다. 같은 이름은 Agent → Project → Global
  순으로 해석하고 Agent별 Required · Available · Disabled 정책을 세션 프롬프트에 반영한다.
  Memory와 Skills 화면은 항목별 배경색을 달리해 정본 단위를 구분한다.
- 라이브러리 Agent는 선택한 프로젝트에 Claude Agent(`.claude/agents/<name>.md`) 또는
  Codex Skill(`.agents/skills/<name>/SKILL.md`) 형식으로 내보낼 수 있다. 내보내기 선택 창은
  화면 포털에 띄워 카드·스크롤 컨테이너에 잘리지 않는다.
- 프로젝트를 열면 새 세션 화면 대신 가장 최근 작업한 세션을 자동 선택하고 대화 기록을 복원한다.
- Worktree 완료 정책에 `자동 병합`과 `병합 제안`을 추가했다. 자동 병합은 정상 완료 시
  미커밋 변경을 자동 커밋하고 안전한 fast-forward만 수행한다. 원본 변경·브랜치 분기·Git 오류가
  있으면 원본을 더 건드리지 않고 실행 경로가 포함된 병합 제안으로 전환한다.
- Worktree 화면에 마지막 자동 반영 단계·시각·경로·dirty/ahead/behind·실패 원인을 접힌 카드로
  저장한다. 중단되거나 누락된 자동 반영은 완료 세션의 Worktree 화면을 열 때 현재 Git 상태부터
  복구하며, 진단 저장 실패가 실제 커밋·병합을 막지 않게 분리했다.
- 자동 병합 완료 안내는 입력창 위 우측 오버레이로 잠시 표시한 뒤 사용자 스크롤·입력 시 체크
  아이콘으로 축소한다. 호버/포커스로 다시 펼치며 대화 높이와 스크롤 위치는 바꾸지 않는다.
- 입력창은 프로젝트별 최근 지시를 보관해 `↑`/`↓`로 탐색한다. 실행 중에도 다음 지시 한 건을
  예약할 수 있고, 예약 당시 세션 ID·CLI 세션 ID·러너를 고정해 현재 작업 종료 후 같은 세션으로
  이어 보낸다.
- Windows 작업표시줄 그룹이 Electron 기본 로고를 사용하지 않도록 BrowserWindow 아이콘과 함께
  패키지 `appId`와 동일한 `AppUserModelID(com.lsj1137.puppeteer)`를 앱 준비 전에 설정했다.

### 0.1.0 후보: 멀티 Agent 오케스트레이션

한 세션에서 하나의 Agent 역할만 적용하는 현재 구조를 확장해 Puppeteer가 여러 provider 프로세스를
직접 실행하고 결과를 중계한다. 기존의 “여러 독립 세션 동시 실행”과 구분한다.

- Lead Agent 1명과 보조 Agent 최대 3명을 한 작업에 구성한다.
- 보조 Agent는 병렬 조사 후 구조화된 결과를 Lead에게 반환하고, Lead가 최종 판단과 답변을 맡는다.
- 초기 버전에서는 Lead만 worktree를 수정하며 보조 Agent는 읽기 전용을 기본으로 한다.
- Agent별 실행환경·상태·권한 요청·토큰·중단을 별도로 표시한다.
- Agent 간 자유 대화보다 `위임 요청 → 결과 반환`을 우선해 순환 대화와 비용 폭증을 막는다.
- Claude 전용 하위 Agent 기능에 종속하지 않고 앱 오케스트레이션 계층에서 Claude와 Codex를 조합한다.
- 전체 취소, 부분 실패, 타임아웃, Lead 종료 시 하위 실행 정리를 세션 생명주기에 포함한다.

이 기능은 사용자에게 보이는 새로운 실행 모델이므로 patch가 아니라 minor 버전 `0.1.0` 후보로 본다.
단, 실제 버전은 안정화 게이트와 호환성 범위를 확인한 뒤 릴리스 시점에 확정한다.

#### 확정된 설계 결정

여기서 말하는 Agent는 Claude CLI의 내장 하위 Agent가 아니라 앱 라이브러리의 Puppeteer Agent
정본(`main/agent-library.ts`, `AgentDef`)이다.

- **위임은 앱이 중재한다.** Lead가 구조화 블록으로 위임안을 출력하면 앱이 파싱해 보조를 실행하고,
  결과를 다음 턴 프롬프트로 Lead에 주입한다. `memory-proposal`과 같은 신호 방식이라 provider에
  중립이다. Claude 전용 하위 Agent 기능은 쓰지 않는다.
- **세션은 늘리지 않는다.** 보조 실행은 세션이 아니라 세션 하위 run(`AgentRun`)이다. 이벤트·승인은
  `runId`로 구분하고, 기존 행의 `runId`가 비어 있으면 Lead로 읽는다.
- **Lead Agent는 자동 선택할 수 있다.** 기존 `main/router.ts`를 세션 시작 경로에서 재사용한다.
- **자동 선택 결과의 실행 여부는 세션 승인 모드를 따른다.** `자동 승인`이면 고른 Agent로 바로
  실행하고, `승인 확인`이면 확인 카드를 먼저 띄운다. 도구 승인과 같은 스위치를 쓴다.
- **Codex 라우터를 만든다.** 현재 라우터는 `claude-haiku` + Claude CLI 인자 고정이라 Codex 전용
  환경에서 돌지 않는다. Codex용 1회 판단 실행 경로를 추가해 두 provider 모두에서 자동 선택이 된다.
- **보조 run은 Agent 없이도 실행할 수 있다.** 일회성 조사에 역할 정본을 강요하지 않는다. 대신 Agent
  정의가 주던 가드가 사라지므로 오케스트레이터가 읽기 전용을 직접 강제하고, provider는 Lead와
  동일하게 고정한다(도메인 지식이 다른 provider로 새지 않게).
- 자동 커밋·병합은 Lead run이 끝날 때만 1회 돈다. 보조 종료가 반영을 유발하면 안 된다.

#### 구현 단계

1. **식별자 도입 (완료)** — `AgentRun` 타입과 `run-start`/`run-status`/`run-result` 이벤트,
   `event.run_id`·`approval.run_id` 컬럼, `agent_run` 테이블, IPC 엔벨로프의 `runId`를 추가했다.
   기존 행의 `run_id`는 비어 있고 Lead run으로 읽는다. 과거 기록을 소급 변환하지 않으며,
   렌더러 reducer는 아직 run 이벤트를 무시하므로 화면 동작은 그대로다.
2. **승인 브로커 run 단위 분리 (완료)** — 브로커의 감시 키를 세션에서 run으로 바꾸고 승인 요청
   폴더를 `.agent-workspace/approvals/<sessionId>/<runId>`로 나눴다. 승인 요청은 `runId`를 싣고,
   승인 모드와 `이 세션에서 허용`은 세션 단위라 그 세션의 모든 run에 함께 적용한다. 세션 종료 시
   `detachSession`으로 보조 감시까지 걷는다. 세션마다 Lead run 한 건(`<sessionId>:lead`)을 기록하고
   상태·비용을 세션과 함께 갱신하며, worktree 자동 반영은 Lead run이 끝났을 때만 돈다.
3. **Orchestrator와 위임 파서 (완료)** — Lead 응답의 ` ```delegate ` 블록을 걷어내 보조 run을
   실행하고, 결과를 다음 턴 프롬프트로 Lead에 주입한다. 위임 실행은 Lead 턴이 끝난 뒤에 돈다
   (프로세스가 겹치면 안 된다). 위임이 걸린 턴은 자동 커밋·병합을 건너뛴다 — 대화가 아직 안 끝났다.
   결과 주입은 `internalPrompt`로 표시해 사용자 지시로 기록하지 않는다. 보조의 대화·도구 이벤트는
   DB에만 남기고 렌더러로 보내지 않는다(Lead가 말한 것처럼 보이면 안 된다).
   읽기 전용은 앱이 강제한다 — Agent 정의가 없어도 `Write`·`Edit`·`NotebookEdit`을 막는다.
4. **상한·병렬·타임아웃·취소 (완료)** — 한 턴에 보조 3개까지 동시에 실행하고, 초과분은 몇 건을
   버렸는지 알린다. 보조 하나가 10분을 넘기면 끊고 실패로 돌린다. 하나가 실패해도 나머지 결과는
   그대로 전달한다. 중지를 누르면 대기 중인 위임을 버리고 실행 중인 보조를 끊으며, 이미 끝난
   보조가 있어도 Lead를 다시 띄우지 않는다.
5. **위임 카드 UI (완료)** — 한 턴에 병렬로 뜬 보조들을 카드 하나로 묶어 대화에 그린다. 보조별
   상태·Agent 이름·비용을 보여주고, 줄을 누르면 반환 요약을 펼친다. 보조의 대화 전체는 싣지 않는다.
6. **Codex 라우터 (완료)** — `router.ts`가 provider별로 갈린다. Claude는 `-p --output-format json`,
   Codex는 `exec --json --sandbox read-only`에 프롬프트를 stdin으로 넣고 마지막 `agent_message`를
   결과로 읽는다. 양쪽 다 도구를 막는다 — 판단만 시키므로 승인 요청이 뜨면 화면이 멈춘다.
   이제 Codex 전용 환경에서도 Agent 자동 선택이 돈다.
7. **Lead 자동 선택 (완료)** — Agent 오버레이에 `자동 선택`을 추가했다. 새 세션의 첫 지시에서만
   라우터를 태우고(이어가는 턴은 세션 Agent가 정본), 결과를 확인 카드로 보여준 뒤 사용자가 정한
   Agent로 세션을 시작한다. 라우터가 고른 대로 곧바로 실행하지 않는 이유는 Agent 지침 전문이 그대로
   모델에 실려 나가기 때문이다. 후보를 바꾸거나 Agent 없이 시작할 수 있고, 라우팅 실패 사유도
   카드에 그대로 보여준다.

### 프로젝트 경로 재연결

- 프로젝트 목록의 재연결 버튼에서 이동한 폴더를 다시 선택할 수 있다. 실행 중인 세션이 있으면
  중단하고, linked worktree가 있으면 `git worktree repair`가 성공한 뒤에만 앱 DB를 변경한다.
- 재연결 시 프로젝트 별칭·정렬·실행환경은 유지하고, 기존 세션의 `projectPath`, worktree 원본,
  Project Memory 이력·대기 제안과 Agent의 프로젝트/절대경로 범위를 새 위치로 갱신한다.
- 폴더 내용이나 Memory 정본 파일을 앱이 임의로 복사·삭제하지 않는다. 같은 새 경로가 이미 등록됐거나
  Git 복구가 실패하면 기존 경로를 유지하고 오류를 표시한다.

## 되짚어 볼 판단들

나중에 뒤집고 싶어질 때 근거를 남긴다.

**배치를 바꾸는 기준은 창 비율이지 폭이 아니다.**
폭 하나로 자르면 큰 화면에서 창을 반쪽으로 붙였을 때도 세로가 되어 버린다. 세로 배치의 전제는
«세로가 남고 가로가 모자란다» 이므로 두 축의 비를 본다. 그리고 임계값을 **둘로 나눈다** —
하나면 정사각에 가까운 창을 끄는 동안 매 프레임 뒤집힌다.

**사용자가 정한 크기는 화면이 좁아져도 지운다고 잊지 않는다.**
창이 좁아지면 Artifacts 를 줄여 그리되 저장값은 그대로 둔다. 창을 다시 넓히면 원래 폭으로
돌아온다. 저장값을 덮어썼다면 창을 한 번 좁힌 것으로 설정이 영영 사라진다.

**크기는 그리드 트랙이 갖고, 패널은 갖지 않는다.**
둘 다 크기를 들고 있으면 트랙만 전환되고 패널은 끊겨 따로 논다. 전환 대상은 한 곳이어야 한다.
같은 이유로 세로 접힘 손잡이 높이는 `auto` 가 아니라 고정값이다 — 접힘과 펼침은 서로 다른
요소라 `auto` 로는 이어서 움직일 값이 없다.

**사용자 텍스트를 명령행 인자에 싣지 않는다.**
프롬프트·지침은 stdin 으로 보낸다. 인자로 실어야만 하는 것(`--agents`)은 **셸을 거치지 않게**
실행한다(`wsl -e` + 고정 스크립트 + `$0`·`$@`). 이스케이프로 막는 방식은 인용 규칙이
provider·OS 별로 갈려 반드시 재발한다. 새 CLI 인자를 추가할 때마다 이 기준을 다시 본다.

**앱은 사실만 모으고, 문장은 모델이 쓴다.**
보고서에서 «무엇을 했는지» 를 앱이 지어내면 틀린 업무보고가 된다. 앱은 기록에서 뽑은 사실만
조립하고 다듬기는 모델에게 맡기되, **원본 사실을 나란히 두어** 사용자가 대조할 수 있게 한다.
`checkpoint.ts` 가 인계 초안에 세운 원칙과 같다.

**일회성 CLI 호출은 세션을 만들지 않는다.**
보고서를 세션으로 돌리면 목록이 오염될 뿐 아니라 **그 세션이 다음 기간 조회에 다시 잡힌다.**
라우팅·보고서처럼 «한 번 묻고 답을 받는» 일은 `cli-once.ts` 를 쓴다.

**접어도 일이 되어야 접는 의미가 있다.**
레일을 접으면 프로젝트 전환·승인 확인·실행 상태가 전부 아이콘으로 남는다. 접었다고 매번 다시
펴야 한다면 접기 자체가 쓸모없다.

**에이전트를 프로젝트가 아니라 전역에서 관리한다.**
`--agents` 로 정의를 인라인 전달할 수 있음을 확인하고 바꿨다. 파일을 러너 홈에 배치하지
않으므로 WSL/Windows 홈이 다른 문제를 아예 피한다. 사용자 지시와 공통 시스템 지침은 stdin으로
전달해 Windows 명령행 길이 제한과 분리한다.

**가져오기는 검토 절차다.**
남이 쓴 지침은 그 자체가 실행 지시다. 요구한 권한을 기본값으로 켜주지 않고, 적용 대상도
비운 채 시작한다. Linked 갱신도 같은 원칙 — 지침은 따라가되 권한은 로컬 값을 유지한다.

**메모리는 CLI 가 읽는 파일이 정본이다.**
앱이 따로 보관했다가 주입하지 않는다. 앱 없이 CLI 를 직접 실행해도 같아야 하기 때문.
프로젝트 메모리를 `AGENTS.md` 정본 + `CLAUDE.md` = `@AGENTS.md` 로 둔 것은
도구 중립 이름 하나로 여러 CLI 가 같은 파일을 읽게 하려는 것이다.

**화면을 사용자 대신 옮기지 않는다.**
앱이 «지금 중요한 것»을 안다고 가정하고 화면을 끌고 가면, 사용자가 보던 것이 사라진다.
예약한 지시가 나갈 때도, 대기 제안을 찾았을 때도, 세션 시작 응답이 늦게 왔을 때도
**알리기만 하고 이동은 사용자가 결정한다.** 예외는 사용자가 직접 누른 결과일 때뿐이다.
자동으로 여는 곳은 한 군데 — 아직 아무것도 고르지 않은 Memory 화면의 대기 제안이다.

**늦게 온 응답은 버린다.**
비동기 응답이 도착했을 때의 화면은 요청할 때와 다를 수 있다. 요청마다 «그때의 대상»을
기억해 두고 지금 화면과 다르면 반영하지 않는다(읽기 번호, 프로젝트 경로 비교).
이 검사를 빠뜨린 자리에서 «눌러도 안 바뀐다»·«탭이 뒤바뀐다»가 반복해서 나왔다.

**Checkpoint 는 세션 ID 가 아니라 텍스트를 넘긴다.**
세션 기록이 러너 홈마다 따로라 ID 는 경계를 못 넘는다. 텍스트면 Claude→Codex,
WSL→Windows, 에이전트 A→B 가 전부 같은 경로로 풀린다.

**worktree 자동 병합은 fast-forward만 허용한다.**
앱이 일반 merge를 실행해 충돌 상태를 남기면 사용자가 어떤 저장소를 복구해야 하는지 알기 어렵다.
원본·작업 폴더가 깨끗하고 브랜치가 갈라지지 않았을 때만 반영하고, 병합 뒤 정리는 별도 판단으로 남긴다.

**새 세션은 기본으로 worktree에서 시작한다.**
세션마다 사용자가 직접 분리 여부를 관리하면 동시에 작업할수록 피로와 실수가 늘어난다. 새 세션만
자동 분리하고, 기존 세션 이어가기는 처음 정한 작업 위치를 유지한다. 자동 생성이 실패하면
경고를 남긴 뒤 현재 폴더에서 계속한다.

**세션이 시작되면 실행 환경을 잠근다.**
바꿀 수 있게 두고 경고하는 방식을 먼저 만들었다가 되돌렸다. 경고는 읽히지 않고,
대화 도중 세션이 갈라진 뒤에야 알아차리게 된다. 바꾸려면 새 세션을 연다.

**없는 값을 지어내지 않는다.**
Codex 는 비용을 주지 않으므로 토큰을 그대로 보여준다. Checkpoint 의 「남은 일」은
비워 두고 사용자가 채운다. 앱이 지어내면 받는 쪽은 그게 틀렸는지 알 방법이 없다.

**조용한 폴백을 만들지 않는다.**
가장 여러 번 데인 부분이다. 문법 강조(WASM·CSP), 폰트(`woff2-variations`),
Codex 훅(`hooks_file` 이라는 없는 키) 모두 **에러 없이 기능만 죽는** 형태였다.
실패는 화면이나 콘솔에 남겨야 진단이 된다.

## 알려진 한계

- 중간 커밋들은 개별적으로 빌드되지 않는다. 초기 대량 작업을 사후에 쪼갠 결과이며
  `main` 끝에서는 정상 빌드된다.
- 홈 라우터는 Claude 로만 돈다(라우팅 프롬프트가 Claude CLI 인자로 짜여 있다).
  판단만 하는 용도라 의도적으로 고정해 두었다.
- 승인 훅은 `PreToolUse` 만 건다. 읽기 계열은 승인을 묻지 않는다.
- Codex 는 `--dangerously-bypass-hook-trust` 가 필요하다. 비관리 훅은 해시 기준 신뢰가
  필요한데 우리 훅 명령은 세션마다 달라진다.
- Electron smoke는 앱 부팅과 runner 감지만 확인한다. 세션 시작·어댑터 이벤트·SQLite 영속화는
  별도 E2E로 자동화했지만 승인 버튼과 worktree 충돌 해결 UI 자체는 아직 수동 검증 영역이다.
