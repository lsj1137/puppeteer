### v0.0.4 현재 작업

#### 세션·대화 UI

- 입력창 위에 실행 환경·Agent·자동 반영 상태를 독립 버튼으로 제공하는 세션 도구 모음을 만들었다.
  도구 모음 전체를 접고 펼칠 수 있고, 각 버튼은 자기 정보만 담은 별도 오버레이를 연다. 접힘
  핸들은 입력 영역을 밀지 않으며 도구 모음 상단 중앙에 붙는 얇은 탭으로 표시한다.
- 대화가 맨 아래에서 벗어나면 우측 아래에 하단 이동 버튼을 표시하고, 하단에 도달하면 숨긴다.
  긴 구분선처럼 공백 없는 문자열도 대화 폭을 밀지 않도록 줄바꿈한다.
- 프로젝트를 선택하면 세션 목록만 불러오는 데 그치지 않고 가장 최근 생성된 세션을 실제 선택해
  대화까지 복원한다.
- 입력 기록 `↑`/`↓` 탐색과 실행 중 다음 지시 한 건 예약을 지원한다. 예약 지시는 새 세션이 아니라
  예약 당시 세션으로 이어 보내며 취소할 수 있다.
- 실행 환경과 Agent 선택은 입력창 바로 위에서 필요한 순간 접근한다. 실행 환경이 왼쪽, Agent가
  오른쪽 순서다.
- 사용량은 기본 접힘 상태에서 아이콘·레이블·진행률·퍼센트만 보여주고 펼치면 상세 내역을 표시한다.
- 실행 중인 세션이 있으면 창 닫기 전에 확인한다. 승인 대기 내역은 앱 재시작·세션 종료 시 폐기하고
  남은 보류 내역은 사용자가 직접 지울 수 있다.

#### 우측 보조 패널

- Git·Artifacts·Files를 탭으로 분리하고 패널 전체를 접을 수 있게 했다. Git 저장소가 아닌 폴더에는
  Git 탭을 표시하지 않는다.
- Files 탭은 프로젝트 또는 세션 worktree의 파일 목록과 읽기 전용 미리보기를 제공한다. 바이너리와
  1MB 초과 파일은 내용을 억지로 읽지 않고 이유를 표시한다.
- 선택된 탭은 기존 형태를 유지하면서 배경만 옅게 조정해 라이트·다크 테마의 문자 대비를 높였다.

#### Worktree·Memory·Git

- 자동 반영은 `자동 병합`과 `병합 제안`을 제공하며 기본값은 자동 병합이다. 변경이 있으면 worktree
  브랜치에 커밋하고, 원본이 안전할 때만 fast-forward한다. 안전 조건 실패 시 원본을 건드리지 않고
  검토 안내와 실행 경로를 남긴다.
- 승인된 Project Memory는 원본의 `AGENTS.md`, `CLAUDE.md`만 별도 커밋한다. 이 때문에 worktree가
  뒤처지면 Memory 충돌이 없는 경우에만 rebase 후 fast-forward하고, 기존 Memory 변경이나 충돌은
  자동으로 덮지 않는다.
- Windows와 WSL에서 줄바꿈 차이만으로 저장소 전체를 dirty로 판단하지 않도록 Git 실행 기준을
  통일했다.
- 동일 worktree의 자동·수동 커밋을 직렬화해 `index.lock` 경쟁을 막는다. 실제 Git 프로세스가 만든
  잠금일 수 있으므로 lock 파일을 무조건 삭제하지 않는다.
- 자동 커밋 제목은 세션명을 복사하지 않고 실제 diff의 파일·작업 유형을 바탕으로 생성한다. 버전
  변경은 `chore: 버전 <version>로 갱신`으로 인식하며 본문에 파일별 변경량을 모은다. 원본에는
  worktree 커밋 이력을 새 커밋으로 복제하지 않고 fast-forward로 보존한다.
- Electron 메인 프로세스는 hot reload로 새 자동 반영 로직이 교체되지 않을 수 있다. Git 로직을
  수정한 뒤 실환경 검증할 때는 앱을 완전히 종료·재시작해야 한다.

#### Agent·Memory·Skills

- 공개 예제 `release-maintainer`에 이어 `agents/agent-creator.md`를 추가했다. Agent 생성 도우미는
  요청을 Agent·Skill·Memory로 먼저 구분하고, Puppeteer가 파싱하는 frontmatter와 `x-workspace`
  스키마로 최소 권한 초안을 만든다. 승인 전에는 파일을 쓰거나 덮어쓰지 않는다.
- Puppeteer Agent는 앱 내부에서 Claude에는 인라인 Agent 정의로, Codex에는 역할 프롬프트로 전달된다.
  Skills는 두 provider 모두에 Required/Available 카탈로그로 연결된다.
- Claude Agent와 Codex Skill은 같은 개념이 아니다. Claude Agent는 역할 프로필로 가져올 수 있지만,
  Codex `SKILL.md`는 반복 절차로 Skill 라이브러리에 넣어 Agent와 조합하는 것이 맞다. 통합 가져오기와
  손실 미리보기는 방향만 정했고 구현은 보류했다.

### Worktree 기능 브랜치

`feat/worktree-merge` 구현은 완료되어 PR #1로 `main`에 병합했다.
macOS에서 다음 흐름을 실제 프로젝트의 두 세션으로 반복 검증했다.

- 새 세션별 worktree 자동 생성과 기존 세션 이어가기
- worktree 변경 커밋과 diff 확인
- 첫 작업의 fast-forward 병합
- 원본이 앞선 두 번째 작업의 재배치와 후속 병합
- 같은 파일의 겹치는 변경에서 좌우 충돌 해결 후 rebase continue
- 병합 완료 상태 갱신, worktree 정리, 정리된 세션의 상태 표시와 재생성
- worktree 승인 알림에서 원본 프로젝트의 같은 세션으로 이동하고 후속 지시 이어가기

현재 자동 검증은 테스트 17개 파일·79개, 타입 검사, 프로덕션 빌드, Electron smoke와
세션·어댑터·SQLite E2E까지 통과했다.
Windows 네이티브에서도 새 세션, 재시작 뒤 복원, 체크포인트, Git 기능, 한글 경로, 승인 훅,
알림을 확인했다.

### v0.0.2 안정화·UX 개선

- `npm run verify`에 가짜 CLI를 이용한 실제 Electron E2E를 포함했다. 세션 시작, 어댑터 이벤트,
  SQLite 저장·복원을 한 번에 확인하며 성공 시
  `Electron E2E passed (session, adapter, SQLite persistence)`를 출력한다.
- Windows 네이티브 `.cmd` 실행을 `cmd.exe /d /s /c`와 명시적 인자 인용으로 고정하고,
  실제 `cmd.exe` 왕복 테스트를 추가했다. 프롬프트의 따옴표가 셸 문법으로 재해석되는 회귀를 막는다.
- OS 알림 클릭 시 새 Electron 창을 띄우는 대신 기존 창을 복원·포커스하고 해당 프로젝트와
  세션으로 이동한다. Windows AppUserModelID와 패키지 아이콘도 적용했다.
- 우상단 실행 환경 표시는 provider 이름(`Claude`, `Codex`)으로 짧게 만들었다. 설정은 탐지된
  환경 전체를 나열하지 않고 `기본 실행 환경` 드롭다운 하나로 정리했다.
- Worktree 관리에서 변경 파일을 바탕으로 커밋 메시지를 자동 제안한다. 큰 lockfile diff는
  전체 선택 모드로 처리해 충돌 해결 화면이 멈추지 않도록 했다.
- 도구 실행 카드(Bash/Edit 등)는 기본으로 접어 대화 밀도를 낮췄다. 입력창 상태를 상위
  `App.tsx`에서 분리해 긴 세션에서도 타이핑 지연이 대화 전체 재렌더링으로 번지지 않게 했다.
- `App.tsx`의 1차 구조 분리를 완료했다. 세션 실행·화면 상태·탐색·명령 팔레트 훅과 대화,
  승인, Artifact, 입력기, 워크스페이스 목록, 사용량, 세션 헤더, 다이얼로그·오버레이를
  별도 모듈로 옮겼다. 2,000줄 이상에서 약 870줄까지 줄였고 `App.tsx`는 화면 조립과
  최상위 상태 연결에 집중한다.
- Worktree 정리가 실패하면 미커밋 변경으로 단정하지 않고 Git의 실제 오류를 표시한다. 실행
  중인 세션은 정리 전에 차단하며, 정리 성공 뒤 병합됐거나 커밋이 없는 작업 브랜치는 안전하게
  함께 삭제한다. 미병합 브랜치는 보존한다.

### v0.0.3 Memory·Skills·작업 연속성

- AI 응답 끝의 구조화된 `memory-proposal` 신호를 사용자 대화에서는 숨기고 검토함에 저장한다.
  Project 또는 현재 전용 Agent Memory만 제안할 수 있으며, 사용자가 최신 정본 기준 diff를
  확인하고 승인해야 실제 Memory 파일에 추가된다. Global Memory는 직접 관리 원칙을 유지한다.
  제안 직후 대화 카드에서 즉시 승인·거절하거나 Memory 화면의 검토함으로 이동할 수 있고,
  Memory 화면은 최신 대기 제안을 자동으로 열어 작은 창에서도 승인 버튼이 잘리지 않게 스크롤한다.
  여러 제안은 전체 정본 diff 대신 각각 실제로 추가될 내용만 보여줘 결정 대상을 분명히 한다.
- Skills를 Global · Project · Agent 3계층으로 관리한다. 같은 이름은 Agent → Project → Global
  순으로 해석하고 Agent별 Required · Available · Disabled 정책을 세션 프롬프트에 반영한다.
  Memory와 Skills 화면은 항목별 배경색을 달리해 정본 단위를 구분한다.
- 라이브러리 Agent는 선택한 프로젝트에 Claude Agent(`.claude/agents/<name>.md`) 또는
  Codex Skill(`.agents/skills/<name>/SKILL.md`) 형식으로 내보낼 수 있다. 내보내기 선택 창은
  화면 포털에 띄워 카드·스크롤 컨테이너에 잘리지 않는다.
- 프로젝트를 열면 새 세션 화면 대신 가장 최근 작업한 세션을 자동 선택하고 대화 기록을 복원한다.
- Worktree 완료 정책에 `자동 병합`과 `병합 제안`을 추가했다. 기본 자동 병합은 정상 완료 시
  미커밋 변경을 자동 커밋하고 안전한 fast-forward만 수행한다. 원본 변경·브랜치 분기·Git 오류가
  있으면 원본을 더 건드리지 않고 실행 경로가 포함된 병합 제안으로 전환한다.
- Worktree 화면에 마지막 자동 반영 단계·시각·경로·dirty/ahead/behind·실패 원인을 접힌 카드로
  저장한다. 중단되거나 누락된 자동 반영은 완료 세션의 Worktree 화면을 열 때 현재 Git 상태부터
  복구하며, 진단 저장 실패가 실제 커밋·병합을 막지 않게 분리했다.
- 자동 병합 완료 안내는 입력창 위 우측 오버레이로 잠시 표시한 뒤 사용자 스크롤·입력 시 체크
  아이콘으로 축소한다. 호버/포커스로 다시 펼치며 대화 높이와 스크롤 위치는 바꾸지 않는다.
- 입력창은 프로젝트별 최근 지시를 보관해 `↑`/`↓`로 탐색한다. 실행 중에도 다음 지시 한 건을
  예약할 수 있고, 예약 당시 세션 ID·CLI 세션 ID·러너를 고정해 현재 작업 종료 후 같은 세션으로
  이어 보낸다.
- Windows 작업표시줄 그룹이 Electron 기본 로고를 사용하지 않도록 BrowserWindow 아이콘과 함께
  패키지 `appId`와 동일한 `AppUserModelID(com.lsj1137.puppeteer)`를 앱 준비 전에 설정했다.

## 되짚어 볼 판단들

나중에 뒤집고 싶어질 때 근거를 남긴다.

**에이전트를 프로젝트가 아니라 전역에서 관리한다.**
`--agents` 로 정의를 인라인 전달할 수 있음을 확인하고 바꿨다. 파일을 러너 홈에 배치하지
않으므로 WSL/Windows 홈이 다른 문제를 아예 피한다. 대신 지침 전문이 argv 로 나가므로
커맨드라인 길이 제한(Windows 32,767자)이 상한이다. 실측 7.4KB 는 정상.

**가져오기는 검토 절차다.**
남이 쓴 지침은 그 자체가 실행 지시다. 요구한 권한을 기본값으로 켜주지 않고, 적용 대상도
비운 채 시작한다. Linked 갱신도 같은 원칙 — 지침은 따라가되 권한은 로컬 값을 유지한다.

**메모리는 CLI 가 읽는 파일이 정본이다.**
앱이 따로 보관했다가 주입하지 않는다. 앱 없이 CLI 를 직접 실행해도 같아야 하기 때문.
프로젝트 메모리를 `AGENTS.md` 정본 + `CLAUDE.md` = `@AGENTS.md` 로 둔 것은
도구 중립 이름 하나로 여러 CLI 가 같은 파일을 읽게 하려는 것이다.

**Checkpoint 는 세션 ID 가 아니라 텍스트를 넘긴다.**
세션 기록이 러너 홈마다 따로라 ID 는 경계를 못 넘는다. 텍스트면 Claude→Codex,
WSL→Windows, 에이전트 A→B 가 전부 같은 경로로 풀린다.

**worktree 자동 병합은 fast-forward만 허용한다.**
앱이 일반 merge를 실행해 충돌 상태를 남기면 사용자가 어떤 저장소를 복구해야 하는지 알기 어렵다.
원본·작업 폴더가 깨끗하고 브랜치가 갈라지지 않았을 때만 반영하고, 병합 뒤 정리는 별도 판단으로 남긴다.

**새 세션은 기본으로 worktree에서 시작한다.**
세션마다 사용자가 직접 분리 여부를 관리하면 동시에 작업할수록 피로와 실수가 늘어난다. 새 세션만
자동 분리하고, 기존 세션 이어가기는 처음 정한 작업 위치를 유지한다. 자동 생성이 실패하면
경고를 남긴 뒤 현재 폴더에서 계속한다.

**세션이 시작되면 실행 환경을 잠근다.**
바꿀 수 있게 두고 경고하는 방식을 먼저 만들었다가 되돌렸다. 경고는 읽히지 않고,
대화 도중 세션이 갈라진 뒤에야 알아차리게 된다. 바꾸려면 새 세션을 연다.

**없는 값을 지어내지 않는다.**
Codex 는 비용을 주지 않으므로 토큰을 그대로 보여준다. Checkpoint 의 「남은 일」은
비워 두고 사용자가 채운다. 앱이 지어내면 받는 쪽은 그게 틀렸는지 알 방법이 없다.

**조용한 폴백을 만들지 않는다.**
가장 여러 번 데인 부분이다. 문법 강조(WASM·CSP), 폰트(`woff2-variations`),
Codex 훅(`hooks_file` 이라는 없는 키) 모두 **에러 없이 기능만 죽는** 형태였다.
실패는 화면이나 콘솔에 남겨야 진단이 된다.

## 알려진 한계

- 중간 커밋들은 개별적으로 빌드되지 않는다. 초기 대량 작업을 사후에 쪼갠 결과이며
  `main` 끝에서는 정상 빌드된다.
- 홈 라우터는 Claude 로만 돈다(라우팅 프롬프트가 Claude CLI 인자로 짜여 있다).
  판단만 하는 용도라 의도적으로 고정해 두었다.
- 승인 훅은 `PreToolUse` 만 건다. 읽기 계열은 승인을 묻지 않는다.
- Codex 는 `--dangerously-bypass-hook-trust` 가 필요하다. 비관리 훅은 해시 기준 신뢰가
  필요한데 우리 훅 명령은 세션마다 달라진다.
- Electron smoke는 앱 부팅과 runner 감지만 확인한다. 세션 시작·어댑터 이벤트·SQLite 영속화는
  별도 E2E로 자동화했지만 승인 버튼과 worktree 충돌 해결 UI 자체는 아직 수동 검증 영역이다.
